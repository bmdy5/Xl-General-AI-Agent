# 小萤“自主发声 + 物理防打扰冷却 + 纯文本拟真打字延迟”系统设计 Spec

## 1. 核心目标
为了实现小萤更灵动、自然且具备情感温度的交互体验，本项目决定对小萤的声音发出策略与消息发送节奏进行底层机制升级：
1. **自主发声决策**：赋予小萤自主拥有声带的决定权，不需被动指令，仅在惊喜、感动、委屈、傲娇等高情感瞬间触发语音。
2. **物理控频防打扰**：网关底层实施“20% 概率过滤 + 15分钟物理冷却期”双重拦截，多发纯文本，少发语音，创造极高惊喜感。
3. **真人打字拟真延迟**：针对日常纯文本消息引入“模拟人类思考（0.3s~0.8s）+ 熟练工打字速度（0.05s/字）”延迟，打破机器冷冰冰的秒回感。

---

## 2. 详细方案设计

### 模块一：小萤 LLM 自主发声人设机制 (`agent/core.py`)
*   **Prompt 调整**：
    在 `STATIC_PROMPT` 中，修改原先死板的“只能在收到明确发语音指令时才回复语音”规定。
    - **发声准则**：小萤可以主动在消息开头附带 `[语音:情绪]`。但仅限在情绪极度高涨（惊喜、害羞、感动、傲娇、委屈）的精彩瞬间。平时 90% 以上的日常闲聊和纯技术解答案例必须使用纯文本，绝不能多发，只有少发、精发才能带给亮哥最极致的惊喜。
    - **硬限字数约束 (<=15字)**：只要决定发声，该句语音文字内容**必须限制在 15 字以内**的极度口语化温馨或傲娇短句（如：“哼！亮哥最差劲了！”、“亮哥，要按时吃饭哦！”），**绝对不允许**将复杂的逻辑解释、长篇技术剖析、代码块放进语音段中。

### 模块二：网关物理防打扰冷却机制 (`agent/gateway.py`)
*   **机制描述**：
    在网关的流式 `text_delta` 解析中，首次检测到 `[语音:情绪]` 标记时：
    1. **获取当前时间戳**：`now = time.time()`
    2. **物理冷却校验**：检查当前时间与上一次成功发声时间 `self._last_voice_time` 的间隔是否大于等于 **15分钟（900秒）**。
    3. **概率强控校验**：检查随机数是否落入 **20% 概率** 区间。
    4. **白名单测试通道豁免**：若亮哥的消息以 `小萤语音测试：` 或 `小萤语音测试:` 开头，则 **100% 绕过**所有冷却和概率限制，确保测试无碍。
*   **状态退化**：
    如果通过校验，允许发声并更新 `self._last_voice_time = now`。
    如果未通过校验（处于冷却期或 80% 的未命中区间），则网关底层**悄悄将 `[语音:情绪]` 标识抹除**，且把网关回复状态强制修改为“非语音消息回复”。该消息随即自动退化为流式纯文本发送。

### 模块三：纯文本真人打字拟真延迟机制 (`agent/gateway.py`)
*   **机制描述**：
    仅针对**纯文本回复的消息（或语音降级退化后的纯文本消息）**在调用 `_send` 或 `_send_chunk` 发送至 NapCat 前注入物理延迟：
    1. **打字延迟计算公式**：
       - `base_delay`（思考时间）：随机在 `0.3` 秒到 `0.8` 秒之间。
       - `char_delay`（打字时间）：`len(text) * 0.05` 秒（模拟 300 字/分钟的盲打手速）。
       - `total_delay`（总延迟）：`min(base_delay + char_delay, 3.5)` 秒（安全锁，上限 3.5 秒防止卡顿）。
    2. **异步等待**：`await asyncio.sleep(total_delay)` 之后，再执行真正的 HTTP 发送。
    3. **开发测试豁免**：以 `小萤语音测试：` / `小萤语音测试:` 开头的消息调试通道，**100% 不经过任何延时**，实现秒级响应。

## 3. 核心数据流逻辑梳理 (Mermaid)

```mermaid
graph TD
    A[亮哥发送请求 raw] --> B{是否以"小萤语音测试"开头?}
    B -- 是 --> C[100% 调试白名单: 豁免所有冷却、概率与拟人延迟]
    B -- 否 --> D[LLM 推理产出 buf]
    D --> E{buf 中是否包含 语音 标识?}
    
    E -- 否 --> F[执行 纯文本打字延迟算法]
    F --> G[asyncio.sleep 延迟]
    G --> H[发送纯文本消息给亮哥]
    
    E -- 是 --> I{当前时间距离上次发声 >= 15分钟 且 命中 20% 概率?}
    I -- 是 --> J[成功合成语音]
    J --> K[更新 self._last_voice_time]
    K --> L[瞬间发送无损情绪语音]
    
    I -- 否 --> M[剥离 语音 标记, 强行退化为纯文本]
    M --> F
```

## 4. 异常与边界场景处理
1. **语音合成崩溃降级**：若 GPT-SoVITS 物理服务发生异常导致合成报错，网关会自动降级为纯文本发送。降级后的纯文本同样正常应用“拟真打字延迟”，实现无缝自愈。
2. **多句 `[SPLIT]` 文本延迟**：若回复中包含 `[SPLIT]` 分句，每个分句分发发送前都会根据句段字数计算并执行打字延迟，完美呈现“一句句打完发出”的连续聊天听感！
