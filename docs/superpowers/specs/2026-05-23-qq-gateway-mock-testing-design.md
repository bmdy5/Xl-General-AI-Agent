# QQ 消息网关全面仿真测试系统设计 (Spec)

本设计规范定义了对 XL Agent 消息网关物理流控、防死锁机制（CSMA/CD）及疲劳度打盹系统的自动化仿真测试方案。测试旨在确保 11 大中间件管道在高频交互、极端并发、以及管理员指令穿透场景下的逻辑正确性，杜绝任何回归退化。

## 方案对比

为了验证 QQ 消息网关的 11 大高内聚中间件管道及状态机逻辑，我们对比了以下两种仿真方案：

### 方案一：全内存离线事件流仿真测试 (推荐)
- **实现原理**：实例化真实的 `QQGateway` 与 `MessageDispatcher` 核心实例，但通过 Mock 拦截其外围网络依赖（Mock LLM 驱动与 Mock SQLite 记忆检索）。通过模拟时间片推进，向网关物理派发连续的 OneBot 消息事件流。
- **优点**：
  - **确定性强**：不受网络波动、大模型 API 额度与上游代理状态影响，100% 稳定运行。
  - **精准时间控制**：可模拟 0.1 秒级别的消息间隔，完美再现“前序消息退避合并”与“推理中途抢话中断并强退协程”的极端并发场景。
  - **执行极速**：数毫秒内即可跑完 6 大核心场景。
- **缺点**：不产生真实的 AI 生成文本（但可通过控制 Mock 返回结果来模拟工具调用与情绪表达）。

### 方案二：端到端 WebSocket 注入测试
- **实现原理**：拉起真实的网关服务，通过外部 Python 脚本建立 WebSocket 模拟 NapCat 客户端，向网关端口发送真实 json payload 并接收大模型生成的真实数据包。
- **优点**：包含真实的网络链路与 AI 生成交互。
- **缺点**：对外部环境依赖过强，执行缓慢，且大模型响应的随机性会导致流控边界断言失效。

**结论**：强烈推荐使用 **方案一**。它符合 MVC 及最小可行性原则，是确保网关防死锁逻辑永不退化的最佳防护网。

## 仿真场景设计

我们将仿真脚本命名为 `tests/test_gateway_simulation.py`，其中包含以下 6 个核心事件流模拟用例：

### 1. 基础消息响应与 RAG 加载
- **模拟事件**：发送一条普通私聊消息。
- **验证指标**：
  - 触发了消息去重、管理员校验与 RAG 检索流水线。
  - 网关最终调用了 `_send` 接口回传 Mock 回复。

### 2. CSMA/CD 载波监听与退避合并 (Carrier Sense)
- **模拟事件**：在 2.0 秒的退避窗口内，用户连续发送三条消息（每隔 0.5 秒发送一条）。
- **验证指标**：
  - 前两条消息的处理器不会被正式拉起，其等待定时器被安全取消并销毁。
  - 第三条消息被最终捕获，网关将三条消息的文本物理合并为单一 Prompt 交付推理，完成去重。

### 3. 流式生成中途抢话中断回收 (Collision Detection)
- **模拟事件**：
  - 用户发送第一条消息，网关开始启动 Mock 大模型的流式推理生成，开始逐字 yield delta。
  - 在生成到一半时（如第 1.0 秒），用户突然发送第二条消息。
- **验证指标**：
  - 网关必须敏锐检测到 Collision 冲突。
  - 正在运行的第一条消息的异步协程被强行 cancel，发送缓冲区清空。
  - 网关立即切换为处理第二条新消息，并向用户宣告重置。

### 4. 脑力疲劳计费与物理打盹苏醒 (Fatigue ＆ Sleep)
- **模拟事件**：非管理员用户发送长文本消息，使其累积疲劳度。
- **验证指标**：
  - 疲劳度扣分按字数累加，当触及 100.0% 时，触发打盹分支。
  - 网关自动在渠道中发送高情商打盹宣告，将状态标记为 `_sleep_modes[session_key] = True`。
  - 随后该非管理员的任何消息都会被直接丢弃拦截。

### 5. 管理员特权唤醒与强行自愈 (Admin Override)
- **模拟事件**：在非管理员因疲劳被打盹拦截期间，管理员亮哥发送一条消息。
- **验证指标**：
  - 管理员消息完美穿透打盹拦截。
  - 全局打盹状态瞬间解除，疲劳度清零。
  - 正在进行的打盹梦境整理协程被强行 cancel 回收，系统自愈重归活跃。

### 6. 一键冻结与解冻控制
- **模拟事件**：管理员在私聊中发送“暂停私聊”，随后非管理员发消息；接着管理员发送“恢复私聊”。
- **验证指标**：
  - 暂停私聊命令生效，非管理员消息被物理拦截。
  - 恢复私聊后，拦截解除，交互通道重归畅通。

## 错误处理与容灾保障

- **超时保护**：每个测试用例均配备 `asyncio.wait_for`，限制最大执行时长为 5.0 秒，防挂起卡死。
- **状态物理重置**：每个用例运行前后，网关的定时器表（`_backoff_timers`）、活跃任务表（`_current_tasks`）及打盹标记（`_sleep_modes`）执行彻底物理重置，确保用例间完全解耦隔离。
