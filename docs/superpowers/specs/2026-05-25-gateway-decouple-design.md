# 系统设计规约 (Spec)：小萤微服务进程化解耦与抖音网关四分拆方案

本设计规约 (Spec) 旨在重塑小萤网关架构，实现各平台网关（抖音、QQ 等）在物理进程层面的彻底隔离，并在代码层面针对超过 500 行的臃肿文件进行职责单一化拆分，奠定多进程微服务网关平台架构。

---

## 📐 1. 架构演进与网络拓扑

### 1.1 原架构 (虚隔离/紧耦合)
```
  ┌──────────────────────────────────────────────────────────┐
  │                   Python 单个物理大进程                   │
  │  ┌──────────────┐         ┌───────────────┐              │
  │  │  QQGateway   ├────────►│  Message      │              │
  │  └──────────────┘         │  Dispatcher   │              │
  │                           └───────▲───────┘              │
  │  ┌──────────────┐                 │                      │
  │  │DouyinGateway ├─────────────────┘ (直接 Python 调用)   │
  │  └──────────────┘                                        │
  └──────────────────────────────────────────────────────────┘
```
* **缺点**：抖音网关模块 `douyin_bot.py` 膨胀到 950 行，且通过直接 Python 调用与 `sender.py`、`dispatcher.py` 紧密耦合；任何一个模块崩溃或重启调试，都会影响到整体。

### 1.2 新架构 (微服务物理隔离)
```
  ┌───────────────────────────────────────┐       ┌───────────────────────────────────────┐
  │        大大脑进程 (Main Brain)        │       │      抖音独立网关进程 (Douyin Port)   │
  │  ┌──────────────┐   ┌──────────────┐  │       │  ┌──────────────┐   ┌──────────────┐  │
  │  │  QQGateway   │   │ Message      │  │       │  │DouyinBrowser │   │DouyinPoller  │  │
  │  └──────────────┘   │ Dispatcher   │  │       │  └──────────────┘   └───────┬──────┘  │
  │                     └──────▲───────┘  │       │                             │         │
  │                            │          │       │  ┌──────────────┐           │         │
  │                            │(HTTP POST│       │  │DouyinSender  │◄──────────┘         │
  │                            │ /event)  │       │  └──────▲───────┘                     │
  │                            │          │       │         │                             │
  └────────────────────────────┼──────────┘       └─────────┼─────────────────────────────┘
                               │                            │
                               └────────────────────────────┘ (HTTP POST /send_private_msg)
```
* **上行链路 (Upstream)**：抖音独立进程中的 `DouyinPoller` 捕获到粉丝消息后，格式化为标准 OneBot JSON，通过 HTTP POST 投递到大脑的 `http://127.0.0.1:8000/event` 接口。
* **下行链路 (Downstream)**：大脑的 `MessageSender` 需要发送抖音私信时，直接向抖音网关进程监听的轻量 HTTP 端口 `http://127.0.0.1:9001/send_private_msg` 投递发送请求，彻底切断 Python 级的代码循环依赖。

## 🛠 2. 代码高雅解耦 (抖音网关四分拆)

为严格执行单个文件小于 500 行的红线规范，原 `douyin_bot.py` 将被优雅解耦分拆为四个职能极度聚焦的微型类：

### 2.1 `douyin_bot.py` (主控框架层)
* **职责**：只保留微服务框架、退避心跳计时器、自愈主循环及 Web 服务暴露。
* **主类**：`DouyinGateway`
* **代码规模**：预计 200 行以内。
* **暴露接口**：启动一个微型 `aiohttp` 端口（默认 9001），提供 `/send_private_msg` 用于接收大脑下发的下行发送消息指令。

### 2.2 `douyin_browser.py` (浏览器与 CDP 驱动层)
* **职责**：专职负责常驻 Chromium / CloakBrowser 浏览器实例的管理、9222 调试端口的 Popen 托管拉起、以及基于 CDP 的无感热接管。
* **主类**：`DouyinBrowserManager`
* **代码规模**：预计 150 行以内。

### 2.3 `douyin_dom_poller.py` (DOM 拟真提取层)
* **职责**：负责页面登录态验证、JS 联合爆破拉起侧边栏、无红点会话的主动心跳，以及 JS 活体 DOM 嵌套去重消息提取。
* **主类**：`DouyinDomPoller`
* **代码规模**：预计 300 行以内。

### 2.4 `douyin_dom_sender.py` (DOM 拟真发送层)
* **职责**：负责物理按键聚焦、拟真打字发送、回车发包及发送结果的双重 DOM 校验。
* **主类**：`DouyinDomSender`
* **代码规模**：预计 150 行以内。

## 🔌 3. 微服务通信接口协议

### 3.1 平台事件上报 (Upstream)
* **方向**：网关进程 -> 大脑进程 (`http://127.0.0.1:8000/event`)
* **方法**：`POST`
* **Payload (OneBot 标准)**：
  ```json
  {
      "post_type": "message",
      "message_type": "private",
      "user_id": "douyin_md5hash",
      "self_id": "douyin_xiaoying",
      "raw_message": "收到的真实文本内容",
      "sender": {
          "nickname": "粉丝昵称",
          "card": ""
      }
  }
  ```

### 3.2 平台消息发送 (Downstream)
* **方向**：大脑进程 -> 抖音网关 (`http://127.0.0.1:9001/send_private_msg`)
* **方法**：`POST`
* **Payload**：
  ```json
  {
      "user_id": "douyin_md5hash",
      "message": "回复的文本内容"
  }
  ```

## 🚦 4. 评审与演进路线

1. **第一阶段**：在 `agent/net_gateway/` 下建立四分拆模块，并建立标准平台独立通信机制。
2. **第二阶段**：在大脑端 (`bot.py` / `main.py`) 启动一个极轻量的 HTTP 接收服务端（端口 8000），使 `MessageDispatcher` 支持 HTTP 形式投递事件。
3. **第三阶段**：在 `Makefile` 中重塑 `make douyin-restart` 指令，实现全自愈、低消耗的极客调试。
