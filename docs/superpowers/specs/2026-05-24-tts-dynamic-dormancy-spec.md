# GPT-SoVITS 动漫语音合成服务动态休眠自愈系统设计规范 (Spec)

## 1. 概述与设计宗旨

小萤的实体动漫声带依赖本地的 `GPT-SoVITS` 物理语音推理引擎。该引擎在 CPU/GPU 内存中需要将大量的深度学习模型权重全部反序列化常驻。
在默认的 FP32 下，会无意义地常驻吃掉宿主机 **3GB** 左右的物理 RAM 内存。

本规范定义了一套**“按需拉起、半精度提速、2小时保活与超时强杀自愈”**的智能休眠调度机制，使小萤在没有语音互动时内存占用为 **0 MB**，只有在有语音互动时自动秒级冷启动，并提供 2 小时高可用保活期，实现物理资源占用与用户交互体验的完美双赢。

---

## 2. 状态机设计 (Dormancy State Machine)

服务运行在以下两个核心状态之间转换：

```
+-------------------------------------------------------+
|                       IDLE (休眠期)                   |
|  - GPT-SoVITS 物理进程未启动 (0% 内存常驻)            |
|  - logs/.tts_state 状态标记为 {"active": false}        |
+-------------------------------------------------------+
                           |
                           | [发声请求触发 (generate_voice)]
                           | 1. 后台秒级以 FP16 半精度命令拉起
                           | 2. 开启最多 4 秒的阻断式端口健康检测
                           v
+-------------------------------------------------------+
|                     ACTIVE (保活活跃期)                |
|  - GPT-SoVITS 物理服务在线运行                        |
|  - 每次成功合成, 自动更新 last_time 时间戳             |
|  - 15s 守护进程探测: 若离线则执行半精度命令自愈拉起    |
+-------------------------------------------------------+
                           |
                           | [last_time 距离当前时间已超 2 小时]
                           | 1. 强力调用 pkill 物理关闭进程释放 3GB RAM
                           | 2. 清理 output/ 等临时音频与日志垃圾
                           | 3. 重置 logs/.tts_state 状态 active=false
                           v
```

## 3. 技术实现要点

### 3.1 极速冷启动优化
在冷启动拉起 GPT-SoVITS API 时，应用 **FP16 半精度** 命令优化（减少浮点数物理存储和计算耗时）：
```bash
nohup ./venv/bin/python3 api_v2.py -a 127.0.0.1 -p 9880 -d cpu -ll half > tts.log 2>&1 &
```
在 Mac M系列 CPU 芯片加速下，半精度加载能够使原本 7 秒的冷启动耗时大幅缩减至 **2 秒左右**。

### 3.2 阻断式轮询自检
在 [`tts.py`](file:///Users/xiaofeng/bot-我的自搭建agent/新的agent/Xl-General-AI-Agent/agent/voice/tts.py) 中，当探测到服务处于休眠（IDLE）时，秒级异步发出拉起命令，并开启最长 4.0 秒的阻断式快速等待轮询（每 200ms 一次 HTTP 探测）。
一旦探测通畅，立刻进行 TTS 编码合成。该策略能够 100% 确保亮哥发起的“首次发声请求”能完整、顺畅地变成语音发送，无降级文本的落差感。

### 3.3 2小时超时物理强杀与磁盘自愈
在 [`scheduler.py`](file:///Users/xiaofeng/bot-我的自搭建agent/新的agent/Xl-General-AI-Agent/agent/net_gateway/scheduler.py) 中，每 15 秒轮询检查 [`logs/.tts_state`](file:///Users/xiaofeng/bot-我的自搭建agent/新的agent/Xl-General-AI-Agent/logs/.tts_state) 状态。
*   若距离 `last_time` 已超过 **7200 秒 (2小时)**，说明服务闲置：
    1. 物理强杀：执行 `pkill -f "api_v2.py"`，强制释放 PyTorch 的所有 CPU/C++ 内存分配。
    2. 磁盘自愈：物理清空 GPT-SoVITS 目录下的 `output` 文件夹、`tts.log` 等垃圾缓存，保障宿主机磁盘绝对清爽。
    3. 复位状态：将 `active` 置为 `false`，彻底转入 IDLE 状态。

## 4. 防坑与维护规范

*   **进程安全拦截**：`logs/.tts_state` 保存在系统的 `logs/` 安全放行区内，保障多进程沙箱读写不被安全机制拦截。
*   **优雅自愈**：只有在保活活跃期（active == True）内，如果服务崩溃离线，守护进程才自动拉起自愈，绝不在静默期（active == False）造成无谓的离线重启冲突。
