# 阶段 4：自动记忆

> 目标：agent 能自动识别并保存重要信息，跨会话复用

---

## 为什么要阶段 4 而不是更早？

**阶段 1-3 是刚需，阶段 4 是体验优化。**

- 没有 web_search，agent 只能操作本地 → 不是"通用"agent
- 没有压缩，长对话会崩溃 → agent 用不久
- 没有自动记忆，agent 每次都是"新来的" → 能用，但不够聪明

所以要这个顺序：**先能用 → 再稳定 → 再聪明**。

---

## 技术选型对比

### 四个框架的记忆方案

| 框架 | 记忆写入方式 | 记忆存储 | 记忆检索 | 复杂度 |
|------|------------|---------|---------|--------|
| **CC** | **模型驱动**：agent 自己决定什么值得记 | Markdown + MEMORY.md 索引 | 轻量模型从文件清单中选（最多 5 个） | 中 |
| **hermes** | **模型驱动**：memory_tool 提供 add/replace/remove/read | Markdown 文件（§ 分隔条目） | 每轮 prefetch 全文注入 | 低 |
| **tinypace** | **后台自动**：压缩时自动存摘要到 SessionState | JSON + 向量索引 | 向量语义检索 + HyDE | 高 |
| **OpenCLAW** | **后台自动 + 强制召回** | Markdown + MEMORY.md | BM25 + 向量混合 | 最高 |

### 选型结论：CC 的模型驱动 + hermes 的 memory_tool 接口

**为什么是 CC 模式？**

CC 的 Auto Memory 核心思路是：**让 agent 自己判断什么值得记**。这意味着：
- 不需要写"何时触发记忆"的规则
- 不需要后台进程
- agent 在对话中觉得某条信息重要，就调 `save_memory` 工具

这与 Anthropic 的 "模型驱动而非规则驱动" 哲学完全一致。

**为什么借鉴 hermes 的 memory_tool？**

hermes 的 `memory_tool.py` 提供了最干净的 CRUD 接口：
- `add`：追加一条记忆
- `replace`：替换已有记忆
- `remove`：删除记忆
- `read`：读取全部记忆

这个 action 参数模式清晰、易理解、直接可抄。

**为什么不用 tinypace 的向量检索？**

向量检索需要：
- embedding 模型（增加 API 成本）
- 向量存储（numpy/faiss）
- 索引维护逻辑

对于目前"几十条记忆"的规模，全文注入 system prompt 完全够用。向量检索的价值在记忆上千条后才体现。

## 最终设计

### 已有基础

我们在阶段 1 已经实现了 `MemoryManager`（CC 模式）：
- `memory/` 目录存 Markdown 文件
- `MEMORY.md` 做索引
- 启动时 `load_context()` 注入 system prompt

**缺的只是"谁来写"**——现在是手动写，阶段 4 让 agent 自己写。

### 新增 `save_memory` 工具

```
save_memory(action: "add"|"replace"|"remove"|"read",
            filename: str,      # add 时需要
            description: str,   # add 时需要（MEMORY.md 中的索引行）
            content: str,       # add/replace 时需要
            old_text: str)      # replace/remove 时的匹配文本
  → 操作 MEMORY.md 和 memory/ 目录下的文件
  → 非只读
  → 需用户审批（防止 agent 乱写记忆污染后续对话）
```

### 注入机制（已有，无需改动）

```
启动 agent → MemoryManager.load_context() → 注入 system prompt
下次对话 → agent 看到上次的记忆 → 行为一致
```

### 与上下文压缩的配合

从对比文档中学到的关键设计：

> OpenCLAW：**压缩前先写 MEMORY.md**——把当前关键信息持久化，压缩才不会丢失

我们的压缩模块（阶段 3）会在压缩前自动调 `save_memory`，确保重要信息在压缩过程中不丢失。
