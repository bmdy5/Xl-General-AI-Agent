# MyAgent 升级路线总览

> 原则：**能复用优先复用，简单优先，每阶段可独立验证**

---

## 当前状态（阶段 1 完成）

```
✅ 核心循环（while-true + AsyncGenerator）
✅ 3 个基础工具（read_file / write_file / bash）
✅ JSONL 会话持久化
✅ MEMORY.md 手动记忆（MemoryManager）
✅ CLI 交互入口
✅ DeepSeek 配置好、已验证
```

## 升级路线

```
阶段 2: 工具系统    阶段 3: 上下文压缩   阶段 4: 自动记忆
   web_search          ~120行 压缩器        save_memory 工具
   (30分钟)            (1小时)              (30分钟)
      │                   │                    │
      ▼                   ▼                    ▼
  能上网搜索          长对话不崩溃          跨会话自动记忆
```

### 依赖关系

```
阶段 2（web_search）   → 独立，不依赖其他阶段
阶段 3（上下文压缩）    → 独立，但建议在阶段 2 之后（agent 更完整了再优化）
阶段 4（自动记忆）      → 依赖阶段 1 的 MemoryManager，与阶段 3 配合使用
```

### 每阶段的"做完标志"

| 阶段 | 验证方式 |
|------|---------|
| 2 | `./run.sh "搜索一下今天有什么科技新闻"` → 返回真实搜索结果 |
| 3 | 连续聊 40 轮不报错，早期对话被自动压缩为摘要 |
| 4 | 告诉 agent 一条偏好 → 退出重启 → 问它"我的偏好是什么？" → 正确回答 |

## 各阶段代码来源总表

| 阶段 | 文件 | 抄了什么 | 改了/简化了什么 |
|------|------|---------|---------------|
| 2 | `web_search_tool.py` | tinypace 的 BaseTool 接口 + 格式化逻辑 | 底层从 BS4 HTML 抓取换成 duckduckgo_search 库 |
| 3 | `compressor.py` | tinypace 的 Head/Tail 分割 + LLM 摘要模式 | 去掉 tiktoken/FileRecovery/Phase2/索引等耦合，加熔断器 |
| 4 | `memory_tool.py` | hermes 的 action 参数模式（add/replace/remove/read） | 底层接已有的 MemoryManager，去文件锁/安全扫描等 |

## 暂时不做的（理由）

| 功能 | 为什么不做 |
|------|-----------|
| **MCP 集成** | MCP 需要运行独立 server，适合"有很多外部工具要接"的场景。目前 3+3 个工具够用 |
| **子代理/多 Agent** | 单 agent 问题还没解决好（压缩+记忆），多 agent 是锦上添花 |
| **Computer Use** | 需要 GUI 环境，与当前 CLI agent 定位不同 |
| **WebSocket/HTTP Server** | 当前 CLI 够用，需要的时候 FastAPI 包装一层即可 |
| **Image2 集成** | 等 agent 本身成熟后，加一个 web_request 工具 30 分钟搞定 |
