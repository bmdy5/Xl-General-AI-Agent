# 阶段 2：工具系统升级

> 目标：让 agent 从"只能操作本地"升级为"能访问互联网的通用 agent"

---

## 升级内容

新增 2 个工具：`web_search`（网络搜索）、`web_request`（HTTP 请求）。

---

## 1. web_search — 网络搜索工具

### 技术选型对比

| 方案 | 原理 | 费用 | 可靠性 | 依赖 |
|------|------|------|--------|------|
| **tinypace HTML 抓取** | BS4 解析 DuckDuckGo HTML | 免费 | ❌ 代码自己承认有 CAPTCHA 问题 | aiohttp + bs4 |
| **duckduckgo_search 库** | 调用 DDG 内部 API | 免费 | ✅ 社区维护，持续更新 | duckduckgo-search |
| **Tavily Search API** | 专为 AI Agent 设计的搜索 API | 付费 | ✅ 最可靠 | API key |

### 选型结论：duckduckgo_search

**为什么不用 tinypace 的方案？**

tinypace 的 `web_search_tool.py` 第 3-5 行自己写了：
> "DuckDuckGo HTML 接口现在有机器人检测（CAPTCHA），直接调用可能失败。建议通过 MCP 工具使用 Web 搜索功能。"

这意味着直接抄 tinypace 的代码会抄一个已知有 bug 的实现。tinypace 保留这个工具更多是为了代码完整性（"我们有 web search"），而不是真的推荐使用。

**为什么不用 Tavily？**

Tavily 确实是最好的 AI Agent 搜索方案，但需要 API key + 付费。现阶段 agent 还处于学习/实验阶段，引入付费依赖不划算。而且你已经配置了 DeepSeek（低成本），加付费搜索会破坏这个策略。

**为什么选 duckduckgo_search？**

- 免费、无需 API key
- 有活跃社区维护的 Python 包
- 返回结构化结果（title、link、snippet），正好适配 AI 消费
- 对中文搜索支持不错

### 代码来源

- **保留 tinypace 的**：BaseTool 接口实现模式、validate_input 验证流程、format_results 格式化逻辑
- **替换的部分**：底层搜索从 `aiohttp + BS4` 换成 `duckduckgo_search` 库
- **简化掉的项目特定依赖**：`create_logger` → 标准 `logging`，去掉 `progress` yield（网络搜索很快，不需要进度反馈）

### 接口设计

```
web_search(query: str, max_results: int = 5)
  → 返回 title + link + snippet 列表
  → 只读工具
  → 可并发
  → 无需用户审批
```

## 2. web_request — HTTP 请求工具（暂缓）

这个工具让 agent 能调用任意 HTTP API（包括你的 Image2 中转站）。

**为什么暂缓？**

你说得对——现在加 web_request 是"为了集成而集成"。先让 agent 本身变强（能搜索、能压缩上下文、能自动记忆），集成外部服务是水到渠成的事。而且有了 web_search 之后，agent 已经有互联网访问能力了。

等 agent 成熟到需要调用 Image2 API 时，加 web_request 只需要 30 分钟——因为工具接口（BaseTool ABC）已经标准化了。

## 实施计划

1. 安装 `duckduckgo-search` 依赖
2. 写 `web_search_tool.py`，复用 tinypace 的结构 + duckduckgo_search 库
3. 在 `main.py` 中注册新工具
4. 验证：让 agent 搜索一条实时信息
