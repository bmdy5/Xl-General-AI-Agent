# 进化系统设计：让 Agent 自我升级

> 老肖 | 2026-05-09

目标：agent 不只是"记住偏好"，而是能**从每次交互中学习，改变自己的行为**。

---

## 1. 记忆 ≠ 进化

先厘清一个关键区别：

| | 记忆 | 进化 |
|------|------|------|
| 做了什么 | 存了一条信息 | 改变了行为 |
| 类比 | 写了一张便签 | 这张便签改变了你下次做事的流程 |
| 例子 | "用户不喜欢 mock" | 下次写测试时自动用真实数据库 |
| 例子 | "这个项目用 Python 3.10" | 不再建议 match 语句 |

**没有行为改变的记忆 = 写了但永远不翻的笔记本。**

四个框架里，只有 hermes 做到了真正的"进化"——它在对话中自主创建 Skill，然后在后续使用中改进 Skill。其他三个框架都只做到了"记忆"。

---

## 2. 进化环：5 步闭环

```
┌──────────────────────────────────────────────┐
│                                              │
│  1. 交互                                     │
│     你说了一句话，agent 做了某件事             │
│                                              │
│  2. 反馈捕获                                  │
│     agent 检测到你的反馈信号                  │
│     • 纠正："不对，应该用绝对路径"            │
│     • 确认："对，就这样"                      │
│     • 新需求："以后都这样做"                  │
│                                              │
│  3. 模式识别                                  │
│     同类反馈出现 N 次 → 形成模式              │
│     "我注意到你总是让我先搜再读文件，          │
│      要不要把这个设成默认流程？"               │
│                                              │
│  4. 行为更新                                  │
│     修改 system prompt / 创建 Skill / 更新记忆 │
│                                              │
│  5. 验证                                      │
│     下次类似场景 → agent 自动用新行为          │
│     你用 /evolution 能看到学到了什么           │
│                                              │
└──────────────────────────────────────────────┘
```

---

## 3. 进化的四种形态

不是所有"学习"都是同一种。参考 CC 的五类记忆，我设计四种进化形态：

| 形态 | 触发信号 | 改变了什么 | 例子 |
|------|---------|-----------|------|
| **偏好进化** | "以后都..."、"我不喜欢..." | system prompt 行为规则 | "以后都给我中文回复" → 下次自动中文 |
| **反馈进化** | "不对，应该..."、"错了" | 工具使用策略 | "不要用 web_search 搜代码问题，用 read_file 读文档" |
| **技能进化** | 完成复杂任务后 | 创建可复用 Skill | 每次部署都做3步 → 变成一个 deploy 技能 |
| **规则进化** | 重复踩坑 | system prompt 约束 | "日志里不要用 f-string" → 加入禁止规则 |

### 3.1 偏好进化

```
交互：用户说"以后回复简洁点，别啰嗦"
捕获：agent 检测到"以后"关键词 → 触发偏好捕捉
模式：如果多次提到"简洁"，确认偏好强度
更新：在 system prompt 中加入"回复风格：简洁直接，不超过3句话"
验证：下次回复自动简洁
```

### 3.2 反馈进化

```
交互：用户说"不对，read_file 之前应该先 grep 定位"
捕获：agent 检测到"不对"+"应该" → 触发反馈捕捉
模式：同类纠正出现 2 次 → 确认为规则
更新：在 read_file 工具的行为指引中加入"优先 grep → 再 read_file"
验证：下次找代码时自动先 grep
```

### 3.3 技能进化（核心，抄 hermes）

```
交互：agent 完成了一个复杂任务（比如部署）
分析：agent 回顾刚才做了什么
  - 1. git add + commit
  - 2. git push
  - 3. ssh 到服务器重启服务
创建：agent 自己写一个 deploy.md 技能文件
  - name: deploy
  - trigger: "部署"、"上线"、"deploy"
  - steps: [git_commit, git_push, ssh_restart]
下次：你说"部署"，agent 自动执行这个流程
```

这是 hermes 最核心的设计——**agent 从自己的经验中创建 Skill**。

### 3.4 规则进化

```
交互：agent 用了 match 语句，Python 3.10 报错
捕获：用户纠正"这个项目用 3.10，不要 match"
模式：单次即可确认为项目规则
更新：system prompt 约束加入"禁止 match 语句（Python 3.10）"
验证：以后永远不会建议 match
```

## 4. 实现设计

### 4.1 新增什么

**两个工具：**

| 工具 | 作用 | 何时触发 |
|------|------|---------|
| `evolve` | 记录一条进化（偏好/反馈/规则/技能） | agent 检测到反馈信号时自动调用 |
| `create_skill` | 创建可复用的技能文件 | agent 完成复杂任务后分析并创建 |

**一个命令：**

| 命令 | 作用 |
|------|------|
| `/evolution` | 展示 agent 从对话中学到的所有东西 |

**一个 system prompt 段：**

```
## Your Evolution System

你是会进化的 Agent。每次交互都是学习机会。

### 进化规则
1. 检测反馈信号：
   - "以后都..."、"我不喜欢..." → 偏好进化
   - "不对..."、"应该..."、"错了" → 反馈进化
   - 完成复杂多步任务 → 技能进化
   - 重复踩坑 → 规则进化

2. 同类信号出现 2 次 → 确认："我注意到你总是 X，要不要我以后都这样？"

3. 用户确认后 → 调用 evolve 工具持久化

4. 下次对话 → 新行为自动生效
```

### 4.2 存储结构

```
~/.my-agent/
├── memory/              # 现有
│   ├── MEMORY.md
│   └── *.md
├── skills/              # 新增：agent 自建的技能
│   ├── deploy.md
│   └── ...
├── evolution/           # 新增：进化日志
│   └── log.jsonl        # 每条进化记录：时间、类型、触发原因、改变了什么
└── sessions/            # 现有
    └── *.jsonl
```

### 4.3 evolve 工具的接口

```python
evolve(
    action: "add" | "list" | "undo",
    evolution_type: "preference" | "feedback" | "skill" | "rule",
    trigger: str,        # 是什么触发了这次进化（用户的哪句话、哪个错误）
    new_behavior: str,   # 改变后的行为是什么
    system_prompt_patch: str  # 要注入 system prompt 的新规则
)
```

## 5. 路线图：分三步进化

### 第 1 步：偏好 + 反馈进化（现在做）

```
能力：agent 能检测你的纠正和偏好，自动记住
新增：evolve 工具 + /evolution 命令
效果：
  "以后说中文" → agent 记住 → 下次自动中文
  "不对，先 grep 再读文件" → agent 记住 → 下次自动先 grep
```

### 第 2 步：技能进化（下次做）

```
能力：agent 完成复杂任务后，自己创建 Skill
新增：create_skill 工具 + skills/ 目录
效果：
  你让 agent 部署了 3 次 → 它自己创建 deploy 技能 → 下次说"部署"就行
```

### 第 3 步：自主进化（以后做）

```
能力：agent 不需要你纠正，自己发现改进空间
参考：hermes 的 Periodic Nudges + 学习循环
效果：
  agent 发现自己经常重复同样的搜索步骤
  → 主动说"我发现我总是在做同样的搜索，要不要我创建一个快捷方式？"
```

## 6. 和之前设计的 save_memory 有什么区别

| | save_memory（阶段4） | evolve（进化系统） |
|------|---------------------|-------------------|
| 记什么 | 事实性信息 | **行为改变** |
| 类比 | 笔记本 | 笔记本 + **自动更新操作手册** |
| 例子 | "用户喜欢简洁代码" | "回复时自动保持简洁" |
| system prompt 变化 | 注入记忆 | 注入**修改后的行为规则** |
| 来源 | CC Auto Memory | hermes 学习循环 + CC 五类记忆 |

**save_memory 是进化的子集。** 进化 = save_memory + 行为改变 + 自主创建 + 验证闭环。
