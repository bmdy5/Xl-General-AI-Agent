# 记忆架构全景：我的 Agent 到底怎么记东西

> 老肖 | 2026-05-09

前 8 篇都在分析别人，这篇画清楚我自己的 agent 记忆系统到底是什么。

---

## 1. 一张图：记忆的完整生命周期

```
                    ┌──────────────────────────────────────────┐
                    │          Agent 记忆系统全景                │
                    └──────────────────────────────────────────┘

  对话中                         磁盘上                         下次对话
  ──────                        ──────                        ──────

  用户说话                                                      用户说话
     │                                                            │
     ▼                                                            ▼
  ┌──────────┐    detect      ┌──────────┐    inject      ┌──────────┐
  │ 反馈捕获  │ ─────────────→ │ 记忆存储  │ ────────────→ │ 上下文注入 │
  │          │                │          │               │          │
  │ 检测信号： │                │ MEMORY.md │               │ system    │
  │ "以后..." │                │ + .md文件  │               │ prompt    │
  │ "不对..." │                │ + 时间戳   │               │ 最新优先   │
  │ 重复纠正  │                │          │               │          │
  └──────────┘                └──────────┘               └──────────┘
     │                            │                           │
     │  agent 调                  │  压缩时                    │  行为
     │  save_memory               │  自动刷新                   │  已改变
     ▼                            ▼                           ▼
  ┌──────────┐                ┌──────────┐               ┌──────────┐
  │ 5类分类   │                │ 迭代进化  │               │ 验证闭环  │
  │          │                │          │               │          │
  │ user     │                │ 时间戳排序 │               │ 下次对话  │
  │ feedback │                │ 最新覆盖旧 │               │ 自动生效  │
  │ project  │                │ 旧版保留   │               │ 不需要    │
  │ reference│                │          │               │ 重新教    │
  │ learn    │                └──────────┘               └──────────┘
  └──────────┘
```

**一句话**：agent 在对话中捕获反馈 → 5 类分类存储 → 压缩时自动刷新 → 时间戳迭代进化 → 下次对话自动注入 → 行为改变 → 新的反馈再次被捕获 → 循环。

## 2. 拆开看每一层

### 2.1 反馈捕获层

**谁在做**：agent 自己（通过 save_memory 工具）

**触发信号**：

| 信号 | 例子 | 归类为 |
|------|------|--------|
| "以后..."、"总是..."、"从不..." | "以后回复用中文" | user 偏好 |
| "不对..."、"应该..."、"不要..." | "不要用 f-string 打日志" | feedback 纠正 |
| "记住..."、"记一下" | "记住 Image2 部署在宝塔" | project 事实 |
| "查一下 xxx 的文档在..." | "API 文档在 docs/api.md" | reference 指针 |
| 重复踩坑 | 第 3 次因同一问题报错 | learn 模式 |

**抄了谁**：
- 信号检测逻辑 → 抄 CC Auto Memory（5 类分类 + 禁止清单）
- 调用方式 → 抄 hermes memory_tool（action 参数：add/replace/remove/read）
- 强制要求 → 抄 openclaw（system prompt 里写"Before answering, check memories first"）

**当前实现**：`agent/tools/memory_tool.py`

### 2.2 分类存储层

**存在哪**：
```
~/.my-agent/memory/
├── MEMORY.md            ← 索引文件，每行格式：
│                         - [描述](文件名.md) `时间戳`
├── coding_prefs.md      ← [user] 编码偏好
├── feedback_test.md     ← [feedback] 测试策略
├── project_image2.md    ← [project] Image2 部署信息
└── ...
```

**为什么是文件而不是数据库**：
- CC 的做法：文件系统就够了，模型原生可读
- 25KB 注入上限（CC 的做法）
- 时间戳排序，最新优先
- 同文件更新保留旧版（hermes 迭代合并模式）

**当前实现**：`agent/memory/manager.py`

### 2.3 上下文压缩联动层

正常对话会越来越长，所以我们加了压缩。但压缩有个风险：**可能把刚捕获但还没存盘的记忆压没了**。

解决方案（抄 openclaw）：**压缩前先确保记忆已刷新**。

```
对话太长 → 触发压缩
  → 1. 检查 MEMORY.md，确认现有记忆安全
  → 2. 调 LLM 做 Head 摘要
  → 3. 用 [历史对话摘要] + 当前对话 替换原始消息
  → 4. 重写 JSONL 文件（清除已被压缩的旧消息）
```

**当前实现**：`agent/compressor.py` + `core.py`

### 2.4 迭代进化层

**解决的问题**：用户说"以后用英文"，agent 记住了。后来用户说"算了还是用中文吧"。旧记忆不会污染新行为。

**机制**：
```
同主题记忆：
  coding_prefs.md (2026-05-09T10:00) → "简洁回复"
  coding_prefs.md (2026-05-09T14:00) → "详细回复，多给例子"

启动时 load_context()：
  1. 按时间戳降序 → 14:00 在 10:00 前面
  2. 同文件去重 → 只保留 14:00 的版本
  3. 注入 system prompt → agent 看到的是"详细回复"
```

**抄了谁**：
- 时间戳格式 → ISO 8601（openclaw 日期文件思路）
- 最新优先 → tinypace Strategy B（只保留最新摘要）
- 旧版保留 → hermes 迭代合并（merge not stack）

**当前实现**：`agent/memory/manager.py` + `agent/core.py` system prompt Evolution Rules

### 2.5 上下文注入层

**注入时机**：每次启动 agent → 构造 system prompt 时

**注入内容**：
```
# Memory (跨会话长期记忆，最新优先)

- [user 编码偏好](coding_prefs.md) `2026-05-09T14:00:00Z`
- [feedback 测试策略](feedback_test.md) `2026-05-09T13:00:00Z`
- [project Image2部署](project_image2.md) `2026-05-09T12:00:00Z`
```

**注入限制**：最多 25KB（CC 的做法），防爆上下文

**抄了谁**：
- 构造时固定 → CC（不是中途动态塞，不会被其他上下文挤掉）
- 索引格式 → CC MEMORY.md
- 时间戳可见 → 自创（让 agent 知道哪个是最新的）

**当前实现**：`agent/core.py` `_build_system_prompt()` → `MemoryManager.load_context()`

## 3. 每条记忆的完整旅程

以"用户纠正测试策略"为例：

```
第 1 步：捕获
  用户: "不对，测试不要用 mock，要连真实数据库"
  agent 检测信号: "不对" + "不要" → feedback 类型

第 2 步：分类存储
  agent 调 save_memory(action="add", memory_type="feedback",
    filename="feedback_test",
    description="测试必须用真实数据库",
    content="老肖偏好：测试时不使用 mock 数据库，必须连接真实数据库进行集成测试。")
  
  → 写入 ~/.my-agent/memory/feedback_test.md
  → MEMORY.md 追加一行: - [反馈 测试必须用真实数据库](feedback_test.md) `2026-05-09T14:30:00Z`

第 3 步：进化迭代（假设后来用户改主意了）
  用户: "算了，单元测试可以用 sqlite 内存库"
  agent 调 save_memory(action="replace", filename="feedback_test",
    content="老肖偏好：集成测试用真实数据库，单元测试可用 sqlite 内存库。")
  
  → feedback_test.md 更新，旧版保留在 <!-- previous version --> 底部
  → MEMORY.md 索引更新为新时间戳

第 4 步：压缩联动
  对话到 75% 阈值 → 压缩触发
  → 压缩前检查 MEMORY.md → 现有记忆安全
  → LLM 摘要旧对话 → [历史对话摘要] + 当前对话

第 5 步：下次注入
  用户重启 agent
  → load_context() 读取 MEMORY.md
  → 时间戳排序 → feedback_test.md 最新版在前
  → 注入 system prompt

第 6 步：行为改变
  agent 看到 system prompt 中的记忆
  → 下次写测试时自动用真实数据库（集成测试）/ sqlite（单元测试）
  → 不需要用户再说一遍
```

## 4. 还缺什么（诚实地说）

| 缺失 | 为什么缺 | 什么时候做 |
|------|---------|-----------|
| **向量语义检索** | 需要 embedding 模型，增加 API 成本 | 记忆 > 50 条后，全文注入太长时 |
| **跨会话全文搜索** | 需要 FTS5 或类似索引 | 历史会话 > 10 个时 |
| **自动提取（非 agent 主动）** | 需要后台流程，当前只有 agent 主动调用 save_memory | 发现 agent 经常"忘了存"时 |
| **周期性提醒（Periodic Nudge）** | hermes 的做法，推动 agent 检查是否有值得存的知识 | 下一步 |
| **知识冲突检测** | 两条记忆矛盾时无法自动发现 | 时间戳排序够用，严重冲突时再搞 |
