# 记忆架构 v2：三层记忆 + 四种注入模式

> 老肖 | 2026-05-09

v1 只讲了"记什么"（5 类分类），v2 补上最关键的缺失：**什么时候注入、注入到哪里、注入多少**。

---

## 1. 记忆不是一类东西，是三层

之前我用 CC 的 5 类（user/feedback/project/reference/learn）当分类，这不对。那是"存什么内容"的分类，不是"记忆本身的分类"。

正确的分层是：

```
┌─────────────────────────────────────────────┐
│            程序性记忆 (Procedural)            │
│  Skills、工作流、行为规则、system prompt      │
│  特点：构造时固定，不随对话变化                  │
│  注入时机：Agent 启动时                         │
├─────────────────────────────────────────────┤
│            长期记忆 (Long-term)               │
│  偏好、反馈、项目事实、外部参考、学习模式         │
│  特点：跨会话持久化，时间戳迭代进化               │
│  注入时机：启动时全量 + 每轮动态检索               │
├─────────────────────────────────────────────┤
│            短期记忆 (Working)                  │
│  当前对话、工具调用链、当前打开的文件              │
│  特点：会话内有效，压缩后变为摘要                 │
│  注入时机：每轮都在消息列表里                     │
└─────────────────────────────────────────────┘
```

### 对照四家框架

| 层 | CC | tinypace | hermes | openclaw | 我们 |
|----|-----|----------|--------|----------|------|
| **程序性** | system prompt 静态段 + Skills | Markdown prompt + Scenario | SKILL.md + 工具集 | 13 个固定段 + skills/ | system prompt（有） |
| **长期** | Auto Memory (5类) + Agent Memory | long_term_memory + 向量索引 | Provider (prefetch/sync) | MEMORY.md + memory/*.md | save_memory + MEMORY.md（有） |
| **短期** | 消息列表 + Session Memory | 消息列表 + active_turn_context | 消息列表 | 消息列表 + workspace 文件 | 消息列表 + compressor（有） |

## 2. 四种注入模式——这才是核心差异

四种框架用了四种完全不同的注入策略：

### 2.1 CC：构造时全量注入

```
Agent 启动
  → 构造 system prompt
    → 静态段（缓存安全）: 身份、规则、工具说明、语气
    → ── cache boundary ──
    → 动态段（每轮重算）: 时间、文件列表、MCP指令
    → Auto Memory: 从 MEMORY.md 挑最多 5 个文件，注入文件名
    → Agent Memory: 直接拼在 system prompt 后面
  → agent "出生"时记忆就已经在里面了
```

**特点**：
- 记忆和 system prompt 同级，不会被后续消息挤掉
- 静态段可缓存（省钱），动态段每轮重算
- 缺点：启动后无法中途加入新记忆（除非重启 agent）

### 2.2 hermes：Hook 注入

```
每轮开始 (on_turn_start)
  → prefetch(query): 根据用户输入检索记忆
  → 结果包在 [MEMORY BLOCK]...[/MEMORY BLOCK] 中
  → 注入到消息列表，不是 system prompt

每轮结束 (sync_turn)
  → 同步本轮新知识到 Provider

会话结束 (on_session_end)
  → 全局摘要、实体提取、关系提取

压缩前 (on_pre_compress)
  → 压缩前钩子，刷新记忆
```

**特点**：
- 每轮都可以注入新的相关记忆
- `[MEMORY BLOCK]` 隔离标签防止注入攻击
- 记忆在消息列表中，不在 system prompt（保护缓存）
- 缺点：记忆可能被后续消息稀释

### 2.3 openclaw：预加载 + 强制召回

```
Agent 启动
  → 1. System Prompt 组装（13 个固定段）
  → 2. 工作区文件注入（AGENTS.md / SOUL.md / USER.md）
  → 3. 技能快照注入
  → 4. 记忆召回注入（Mandatory recall step）
  → 5. 历史消息加载
  → 6. 当前用户消息追加

每轮
  → memory_search 工具描述中写死 "Mandatory recall step"
  → 模型回答前必须先调 memory_search
```

**特点**：
- 工作区文件在启动时预加载（不是动态的）
- "强制召回步骤" 不是建议，是写在工具描述里的硬性要求
- BM25 + 向量混合搜索，maxInjectedChars=4000 防爆
- 缺点：启动后工作区文件不更新

### 2.4 tinypace：XML 块注入

```
启动时
  → System Prompt 从 .md 文件加载

每轮
  → long_term_memory 格式化为 <memory_block> XML
  → 注入到 system prompt
  → active_turn_context 格式化为 <CURRENT_TURN_CONTEXT> XML
  → 注入到消息列表
```

**特点**：
- XML 标签结构清晰，不污染消息角色
- System Prompt 和消息列表分开注入
- 缺点：只保留最新摘要，旧摘要被覆盖

## 3. 注入机制全景对比

| 维度 | CC | hermes | openclaw | tinypace |
|------|-----|--------|----------|----------|
| **何时注入** | 构造时（启动） | 每轮 prefetch + sync | 启动时预加载 | 每轮 format |
| **注入位置** | system prompt | 消息列表 [MEMORY BLOCK] | system prompt + 工具输出 | XML 块（两处） |
| **注入量** | 最多 5 文件 / 200行25KB | 按 query + 1个外部Provider | 每文件20k字符 / 搜索4k字符 | 仅最新摘要 / 20文件 |
| **缓存策略** | 静态/动态边界 | 技能作为用户消息保缓存 | 无显式缓存 | 无显式缓存 |
| **触发机制** | API调用时重算动态段 | on_turn_start / sync_turn | 每次 agent run | 会话开始 + 压缩后 |
| **多Agent** | Agent Memory scope + Snapshot | on_delegation 钩子 | sessionKey 隔离 | 无 |

## 4. 我们应该怎么改

### 当前状态

```
我们只有一种注入方式：
  启动时 → load_context() → 拼到 system prompt 后面
  
问题：
  - 启动后无法动态注入新记忆
  - 没有强制召回机制
  - system prompt 没有静态/动态分离
  - 没有每轮 prefetch
```

### 目标架构

```
┌─────────────────────────────────────────────────────┐
│                  System Prompt                       │
│  ┌───────────────────────────────────────────────┐  │
│  │ 静态段（缓存安全）                              │  │
│  │ - 身份: "你是老肖的私人Agent"                    │  │
│  │ - 规则: 进化规则、工具使用指南                    │  │
│  │ - 禁止清单                                      │  │
│  ├───────────────────────────────────────────────┤  │
│  │ ── cache boundary ──                           │  │
│  ├───────────────────────────────────────────────┤  │
│  │ 动态段（每轮重算）                              │  │
│  │ - 当前时间、工作目录                             │  │
│  │ - 长期记忆索引（MEMORY.md 最新优先）             │  │
│  └───────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────┐
│              消息列表（每轮动态）                      │
│  ┌───────────────────────────────────────────────┐  │
│  │ [MEMORY BLOCK] (抄 hermes)                     │  │
│  │ - 每轮 prefetch 相关记忆（基于用户输入的检索）     │  │
│  │ - 隔离标签防注入                                │  │
│  │ - maxInjectedChars 4000 (抄 openclaw)          │  │
│  ├───────────────────────────────────────────────┤  │
│  │ [CURRENT TURN CONTEXT] (抄 tinypace)            │  │
│  │ - 压缩后恢复当前任务上下文                        │  │
│  │ - TODO 工作流指令                               │  │
│  └───────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────┐
│              工具层（强制召回）                        │
│  - save_memory 描述中写 "Mandatory recall step"      │
│  - 模型回答偏好类问题前必须先 check memory            │
│  - memory_search 工具（未来）                        │
└─────────────────────────────────────────────────────┘
```

### 具体改动

| 优先级 | 改动 | 抄谁 | 效果 |
|--------|------|------|------|
| **P0** | system prompt 静态/动态分离 | CC | 静态段可缓存，省钱；动态段每轮更新记忆 |
| **P0** | [MEMORY BLOCK] 每轮 prefetch | hermes | 每轮根据用户输入动态注入相关记忆 |
| **P1** | 强制召回步骤 | openclaw | save_memory 工具描述写死 "先搜索记忆" |
| **P1** | 注入上限 | openclaw+CC | MEMORY.md 200行/25KB，per-turn 4000字符 |
| **P2** | on_session_end 深度处理 | hermes | 会话结束时全局摘要 + 实体提取 |
| **P2** | [CURRENT TURN CONTEXT] | tinypace | 压缩后恢复任务上下文 |
| **P3** | memory_search 工具 | openclaw | BM25 + 未来向量混合搜索 |

## 5. 改完后的对比

| 维度 | 改之前 | 改之后 |
|------|--------|--------|
| **注入时机** | 仅启动时 | 启动时 + 每轮动态 |
| **注入位置** | system prompt 尾部 | system prompt + [MEMORY BLOCK] |
| **注入量** | 全量（可能超限） | 启动全量 + 每轮上限4000字符 |
| **缓存** | 无 | 静态段可缓存 |
| **召回机制** | 被动（看运气） | 强制召回 + 每轮 prefetch |
| **防注入** | 无 | [MEMORY BLOCK] 隔离标签 |
