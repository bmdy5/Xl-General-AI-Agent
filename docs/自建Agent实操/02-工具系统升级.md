# 阶段 2：工具系统升级 — 让 Agent 能上网

> 老肖 | 2026-05-09

目标：加 `web_search` 工具，让 agent 从"只能操作本地"变成"能访问互联网"。

验收标准：`./run.sh "搜索一下今天有什么科技新闻"` 返回真实搜索结果。

---

## 1. 为什么先做这个

阶段 1 的 agent 只能操作本地文件系统。一个"通用"agent 至少要能获取外部信息。

对比 Anthropic 对 Agent 的定义：

> Agent 从与人类指令开始，任务明确后独立规划和操作，中途可暂停请求人类反馈。

"独立规划和操作"需要信息输入。没有搜索能力，agent 只能靠训练数据里的知识（有截止日期）。

## 2. 选型：为什么不用 tinypace 的方案

tinypace 的 `web_search_tool.py` 用 **DuckDuckGo HTML 抓取 + BeautifulSoup**。但它自己在第 3-5 行承认了问题：

```python
"""
注意：DuckDuckGo HTML 接口现在有机器人检测（CAPTCHA），直接调用可能失败。
建议通过 MCP 工具使用 Web 搜索功能（如 Tavily MCP Server）。
"""
```

如果直接抄，等于抄一个有已知 bug 的代码。

### 方案对比

| 方案 | 费用 | 可靠性 | 依赖 |
|------|------|--------|------|
| tinypace HTML 抓取 | 免费 | ❌ CAPTCHA 问题 | aiohttp + bs4 |
| duckduckgo_search 库 | 免费 | ✅ 社区维护 | duckduckgo-search |
| Tavily API | 付费 | ✅ 专为 AI Agent 设计 | API key |

**选 duckduckgo_search**。理由：
- 免费、无需 API key——和 DeepSeek 的低成本策略一致
- 返回结构化结果（title + link + snippet），AI 天然适合消费
- 社区活跃，遇到问题有人修

Tavily 确实更好（专为 Agent 设计、结果更精准），但现阶段不值得为了一个工具引入付费依赖。

## 3. 代码来源

| 部分 | 来源 | 怎么处理 |
|------|------|---------|
| BaseTool 接口实现 | tinypace `base_tool.py` | 沿用已有接口 |
| 工具定义格式 | tinypace `web_search_tool.py` | 保留 TOOL_DEFINITION 结构 |
| 结果格式化 | tinypace `web_search_tool.py` | 保留 `_format_results()` 逻辑 |
| 底层搜索 | **换掉** → duckduckgo_search 库 | 不抄 BS4 部分 |
| 日志 | tinypace → 标准 logging | 去掉 create_logger |

## 4. 工具接口

```
web_search(query: str, max_results: int = 5)
  → 返回 [{title, link, snippet}, ...]
  → is_read_only = True（可并发）
  → needs_permissions = False（无需审批）
```

这是一个纯信息获取工具，不会修改任何东西，所以设为只读、不需要审批。

## 5. 验证方式

```bash
./run.sh "搜索一下今天有什么科技新闻，列出前3条"
# 期望：返回真实的、有时效性的搜索结果

./run.sh "帮我查一下 Python asyncio 的官方文档怎么说的"
# 期望：返回 Python 官方文档相关链接
```
