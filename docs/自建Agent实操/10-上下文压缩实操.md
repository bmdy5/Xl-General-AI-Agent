# 阶段 5：上下文压缩 — 长对话不崩溃

> 老肖 | 2026-05-09

目标：长对话自动压缩旧历史，不爆上下文窗口。

验收标准：连续聊 40 轮不报错，早期对话被自动压缩为摘要。

---

## 1. 为什么 P0 是压缩而不是向量库

我之前纠结了很久要不要先做向量库（KI 蒸馏 + 语义检索）。但冷静下来想：

- 没有压缩 → 聊 30 轮窗口爆了 → agent 直接挂
- 没有向量库 → 记忆检索精度差一点 → agent 还能用

**先解决"挂掉"的问题，再优化"精度"。**

## 2. 选了哪些设计

| 机制 | 来源 | 为什么选 |
|------|------|---------|
| Head/Tail 分割 | tinypace | 最后一条用户消息是分界线，逻辑清晰 |
| LLM 结构化摘要 | hermes | 强制输出：任务/约束/已完成/当前状态/关键决策/用户偏好 |
| 熔断器 | CC | 连续 2 次失败 → 跳过，防止压缩死循环 |
| 压缩前记忆刷新 | openclaw | 压缩前确保现有记忆不会丢 |
| Token 估算 | 自创 | `len(str)/4`，比 tiktoken 简单，误差 20% 但够用 |
| 触发阈值 | 75% | 比 tinypace 的 92% 保守，给当前轮留更多空间 |

## 3. 具体实现

### 3.1 触发时机

```python
def should_compress(self, messages):
    if self._circuit_open:       # 熔断器打开 → 跳过
        return False
    if len(messages) < 6:        # 太少消息不值得压
        return False
    estimated = estimate_tokens(messages)
    return estimated >= max_tokens * 0.75  # 75% 阈值
```

### 3.2 压缩流程

```python
async def compress(messages, memory):
    1. 找最后一条 user 消息 → split_idx
    2. Head = messages[:split_idx]    # 旧对话
    3. Tail = messages[split_idx:]     # 当前轮保留
    4. 格式化 Head 为文本
    5. 调 LLM 做结构化摘要（hermes 模板）
    6. 截断过长摘要（max_summary_tokens * 4 字符）
    7. 返回 [summary_system_msg] + Tail
```

### 3.3 hermes 结构化模板

```
任务：当前正在做什么
约束：有哪些限制条件
已完成：完成了哪些步骤和结果
当前状态：进展到什么阶段
关键决策：做了哪些重要决定
用户偏好：用户表达了哪些偏好或纠正
```

### 3.4 熔断器

```python
try:
    response = await llm.chat(messages=[...])
    summary = response["content"]
    if not summary or len(summary) < 20:
        failures += 1
        if failures >= 2:  # 连续 2 次 → 熔断
            circuit_open = True
except Exception:
    failures += 1
    # 同上

# 成功后
failures = 0  # 重置
```
