## 2. 逐框架分析：每家的独门绝技

### 2.1 CC 最强：记忆分类 + 会话摘要

**独门绝技一：五类记忆 + 禁止清单**

CC 不只告诉你"要记什么"，还告诉你"不要记什么"：

```
✅ 记：user（偏好）、feedback（反馈）、project（决策）、reference（指针）、learn（模式）
❌ 不记：代码结构（读代码就有）、git历史（git log就有）、
         CLAUDE.md已有的（别存两份）、临时任务（过期的信息）
```

这个禁止清单极其重要。没有它，agent 会把所有东西都记下来——包括"今天读了 main.py 第 30 行"这种垃圾信息。

**独门绝技二：会话摘要的自然断点检测**

```
触发条件：token > 10000（首次） AND 增量 > 5000 AND 工具调用 > 3次
          OR token增量 > 5000 AND 当前轮没有进行中的tool_use

关键：!hasToolCallsInLastTurn
→ 不在 agent 连续调工具链中间截断
→ 在"自然断点"写摘要
```

**独门绝技三：forked subagent 沙箱化**

```
写摘要的不是主 agent，是 fork 出来的子 agent
子 agent 只能用 FileEditTool，且路径精确匹配 memory 文件
FileReadTool、FileWriteTool 都被 deny
```

这防止了 memory 系统变成权限漏洞。

### 2.2 tinypace 最强：压缩驱动记忆

**独门绝技：记忆由压缩自然产生**

```
正常对话 → token 到 92% → 触发压缩 → 压缩产物自动存入 long_term_memory
```

不需要单独的"记忆提取"步骤。压缩和记忆是一件事的两个面。
CC 的 Session Memory 是独立的后台流程，tinypace 把它整合进了压缩管线。

**问题**：只保留最新摘要，旧摘要被覆盖。
**补偿**：旧历史通过 `search_memory` 工具的向量索引访问。

### 2.3 hermes 最强：学习循环 + 跨会话搜索

**独门绝技一：自主学习循环**

```
执行复杂任务 → 提取经验 → 自主创建 Skill → 使用中改进 → 下次自动调用
```

这是四个框架里唯一有"成长性"的。CC 的记忆是被动记录，hermes 的记忆是主动学习。

**独门绝技二：FTS5 跨会话全文搜索**

```
所有历史会话 → SQLite FTS5 索引 → 每次查询 → 全文搜索匹配 → LLM 摘要 → 注入
```

CC 只搜当前会话，tinypace 只搜当前会话。只有 hermes 能做到"三个月前我们聊过这个，当时你的结论是..."。

**独门绝技三：Provider 插件模式**

```python
class MemoryProvider:
    async def prefetch(self, query)     # 每轮开始检索
    async def sync_turn(self, messages) # 每轮结束同步
    async def on_session_end(self)      # 会话结束总结
    async def on_delegation(self, info) # 子Agent完成后
```

最干净的接口设计。内置记忆、Mem0、Supermemory 都是子类实现。

**独门绝技四：[MEMORY BLOCK] 注入隔离**

```
[MEMORY BLOCK]
... 召回的记忆内容 ...
[/MEMORY BLOCK]
```

这个隔离标签防止模型把"被召回的历史资料"误解成"当前用户的新命令"。

### 2.4 openclaw 最强：混合检索 + 防爆设计

**独门绝技一：BM25 + 向量混合检索**

| 方式 | 强项 |
|------|------|
| BM25（关键词） | 精确匹配：文件名、函数名、配置项、"postgres" |
| 向量（语义） | 理解："数据库连接失败" = "postgres 报错" |

两者互补。纯向量搜索对精确术语匹配不好，纯关键词搜索不懂同义词。

**独门绝技二：强制召回步骤**

```typescript
// 工具描述里的措辞是刻意的：
"Mandatory recall step: semantically search MEMORY.md + memory/*.md..."
```

不是在 system prompt 里"建议"模型搜索记忆，而是在工具定义里**强制要求**。模型必须在执行任务前先调 memory_search。

**独门绝技三：FallbackManager 在线自愈**

```
QMD 后端失败 → primaryFailed=true → 懒加载 builtin → 后续请求走 fallback
下次请求 → 重新尝试 QMD → 成功则恢复
```

不是"一个后端挂了就永远用不了"，而是会自动尝试恢复。

**独门绝技四：注入上限**

```
maxInjectedChars = 4000
```

你可能有 1000 条记忆、100 次搜索结果，但注入 prompt 的永远不会超过 4000 字符。防爆。

## 3. 我的方案：取各自最强，组合成一个

### 3.1 总架构

```
MemorySystem（我的）
│
├── 1. 记忆分类器 (抄 CC)
│   ├── 5种类型：user / feedback / project / reference / learn
│   └── 禁止清单：不记代码结构、git历史、已有文档、临时任务
│
├── 2. 会话摘要器 (抄 CC)
│   ├── 触发：10k首次 / +5k增量 / +3工具调用
│   ├── 自然断点检测：不在工具链中间截断
│   └── 写入：LLM生成结构化摘要
│
├── 3. 存储层 (CC + tinypace)
│   ├── 长期记忆：Markdown文件 + MEMORY.md索引 (CC)
│   ├── 会话摘要：JSONL内联存储 (tinypace)
│   └── 压缩联动：压缩前自动刷新记忆 (openclaw + tinypace)
│
├── 4. 检索层 (openclaw + hermes)
│   ├── 简易BM25：关键词精确匹配 (抄openclaw)
│   ├── 强制召回：save_memory工具描述中要求先搜索 (抄openclaw)
│   └── 跨会话搜索：搜所有历史JSONL文件 (简化hermes FTS5)
│
├── 5. 注入层 (hermes + openclaw)
│   ├── [MEMORY_BLOCK] 隔离标签 (抄hermes)
│   └── 注入上限：25KB/200行 (抄CC+openclaw)
│
└── 6. 接口层 (hermes)
    └── MemoryProvider ABC：可插拔后端 (抄hermes)
```

### 3.2 为什么这个组合

| 维度 | 最佳来源 | 为什么选它 |
|------|---------|-----------|
| **记什么** | CC | 唯一有"禁止清单"的，防止记忆垃圾 |
| **何时记** | CC + tinypace | CC的自然断点+tinypace的压缩联动 |
| **怎么存** | CC | Markdown+索引，零依赖，模型原生可读 |
| **怎么搜** | openclaw | BM25+向量混合，比纯向量更准 |
| **搜什么范围** | hermes | 跨会话，不止当前 |
| **怎么注入** | hermes | [MEMORY_BLOCK]隔离标签防注入 |
| **怎么限制** | openclaw+CC | 4000字符上限+25KB文件上限 |
| **怎么扩展** | hermes | MemoryProvider ABC，换后端不改上层 |

### 3.3 但我不一次做完

分三步落地：

```
第1步（现在）：save_memory 工具 + 5类分类 + 禁止清单
    → agent 能自己决定记什么，不会记垃圾信息

第2步（下次）：会话摘要器 + 自然断点检测
    → 长会话自动生成摘要，压缩时用摘要代替原始对话

第3步（以后）：BM25 检索 + 跨会话搜索
    → "我们三个月前聊过什么"能搜出来
```

## 4. 第1步具体设计：save_memory 工具

### 理由

CC 和 hermes 都用了一个看似简单的设计——**把记忆写成一个工具，让 agent 自己决定何时调用**。

这比"后台自动提取"好在哪里？
- Agent 最清楚什么值得记，不需要额外的提取算法
- 用户能看到 agent 在"记东西"，透明
- 如果 agent 记错了，用户直接说"别记这个"
- 实现简单——就是加一个 Tool

### 借鉴来源

| 设计点 | 来源 |
|--------|------|
| action 参数 (add/replace/remove/read) | hermes memory_tool.py |
| 5种类型分类 | CC Auto Memory |
| 禁止清单 | CC Auto Memory（写在工具描述里，让模型遵守） |
| 两步法写入 | CC（先写topic文件 → 再加索引行） |
| [MEMORY_BLOCK] 隔离 | hermes |
| needs_permissions=True | CC（记忆写入需用户审批） |
