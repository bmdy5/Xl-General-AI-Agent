## 2. CC 的进化机制

### 核心思路：系统帮你记住，下次自然生效

CC 不是 agent 自己主动进化，而是**系统在后台偷偷帮你提取、存储、注入**。Agent 甚至不知道"进化"正在发生——它只是下次启动时发现 system prompt 里多了一些内容。

### 具体怎么做的

**第 1 步：提取（后台，不阻塞主流程）**

```
Auto Memory 触发条件：
  后台调度 → 不阻塞主流程
  只用最近若干消息 → 不全量扫描
  fork 一个子 agent → 沙箱隔离

Session Memory 触发条件：
  首次：token > 10,000
  后续：增量 ≥ 5,000 AND (工具调用 ≥ 3 次 OR 当前轮无进行中的 tool_use)
```

**第 2 步：分类存储**

不是存一条"用户说了什么"，而是**五类记忆**：

```
user:     "老肖是后端工程师，主要用 Python/FastAPI"
feedback: "测试要用真实数据库，不要 mock"
project:  "Image2 项目部署在腾讯云+宝塔"
reference:"Image2 后端 API 文档在 docs/API.md"
learn:    "这个项目的日志配置容易出问题，注意检查"
```

**第 3 步：注入（构造时固定，不是动态塞）**

```
每次启动 agent → 构造 system prompt 时
  → 读 MEMORY.md 索引
  → 调轻量模型从清单中选最多 5 个相关文件
  → 拼接到 system prompt 后面
  
关键：不是 agent 跑起来后中途塞的
     是 agent "出生前"就写进 system prompt 的
     和 system prompt 同级，不可能被其他上下文挤掉
```

### CC 进化 = 被动但可靠

- 不是 agent 主动说"我学到了什么"
- 而是系统帮你做完了提取、分类、存储、注入的全流程
- agent 下次醒来时，自然就会用新的行为

## 3. openclaw 的进化机制

### 核心思路：每个事件都是学习机会

openclaw 有最完整的**钩子系统**，进化发生在每一个事件回调里。

### 具体怎么做的

**第 1 步：上下文组装（每次都重新注入）**

```
每次对话的上下文组装顺序：
  1. System Prompt 组装
  2. 工作区引导文件注入 ← AGENTS.md / SOUL.md / USER.md
  3. 技能快照注入
  4. 记忆召回注入 ← "Mandatory recall step" 强制先搜记忆
  5. 历史消息加载
  6. 当前用户消息追加
```

**第 2 步：钩子捕获（6 个拦截点）**

```
pre-agent-run   → 模型调用前拦截
post-agent-run  → 模型调用后处理
before_tool_call → 工具执行前可阻断/改写参数
after_tool_call  → 工具执行后审计 ← 每个工具调用都是学习数据
on_turn_start    → 每轮开始
on_turn_end      → 每轮结束
on_session_end   → 会话结束 ← 全局总结+实体抽取
```

**第 3 步：工作区文件（进化的载体）**

```
USER.md    → 用户偏好（类似 CC 的 user memory）
SOUL.md    → agent 性格/规则（类似 CC 的 feedback memory）
AGENTS.md  → 项目级指令（类似 CC 的 project memory）
```

这些文件不是只读的——agent 可以在对话中修改它们。修改后，下次上下文组装时自动注入新版本。

**第 4 步：强制召回（确保不遗忘）**

```
memory_search 工具的描述里写着：
"Mandatory recall step: semantically search MEMORY.md + memory/*.md..."

这不是建议，是强制要求。Agent 在执行任务前必须先搜记忆。
```

### openclaw 进化 = 事件驱动 + 强制不遗忘

- 每个 after_tool_call 都是反馈捕获点
- 每个 on_session_end 都是全局学习点
- "Mandatory recall step" 确保过去的反馈永远不会被遗忘
- workspace 文件（USER.md/SOUL.md/AGENTS.md）是进化的载体

## 4. hermes 的进化机制

### 核心思路：Agent 自己决定学什么、怎么学

hermes 是唯一让 agent **主动**学习的框架。

### 具体怎么做的

**第 1 步：Prefetch（每轮开始都检索相关记忆）**

```
每次对话开始 → prefetch(query) → 检索相关记忆 → [MEMORY BLOCK] 注入
```

**第 2 步：Sync（每轮结束都同步新记忆）**

```
每轮结束 → sync_turn(messages) → Provider 提取新记忆 → 持久化
```

**第 3 步：自主创建 Skill（独门绝技）**

```
完成复杂任务 → agent 分析"刚才做了什么、哪里可以复用"
  → 自主生成 Skill 文件
  → 下次遇到类似任务自动调用
```

**第 4 步：Skill 自我改进（独门绝技）**

```
Skill v1 → 使用 → 发现改进点 → Skill v1.1 → 继续用 → v1.2 → ...
```

不是静态的模板，是在使用中进化的。

**第 5 步：Periodic Nudges（主动推动）**

```
系统定期提醒 agent："有没有值得持久化的知识？"
→ agent 检查最近对话
→ 自己决定要不要存、存什么
```

### hermes 进化 = agent 主动学习

- agent 不是被动接收反馈
- agent 自己决定"这个值得学"
- agent 自己创建 Skill
- agent 自己改进 Skill
- 系统用 Periodic Nudges 推动 agent 保持学习节奏

## 6. 我应该怎么组合

不是三选一，是**取各自最强，组合成我自己的进化系统**：

```
进化系统（我的）
│
├── 记什么 → 抄 CC
│   └── 5类记忆 + 禁止清单（知道什么不该记）
│
├── 触发时机 → 抄 openclaw + CC
│   ├── after_tool_call 钩子：每次工具调用完检查反馈（openclaw）
│   ├── on_session_end 钩子：会话结束全局总结（openclaw）
│   └── 自然断点检测：不在工具链中间截断（CC）
│
├── 存储 → 抄 CC + openclaw
│   ├── MEMORY.md 索引 + Markdown 文件（CC）
│   └── evolution.md 进化日志（openclaw 的文件更新模式）
│
├── 检索与注入 → 抄 openclaw + CC
```

## 8. 最关键的区别（我之前搞错的）

我之前说 CC 和 openclaw "没有进化"，这是错的。准确地说：

- **CC 有进化**——系统在后台（forked subagent）帮你提取反馈 → 存为5类记忆 → 下次构造时注入 system prompt → 行为改变。但 agent 自己不知道"进化"在发生。
  
- **openclaw 有进化**——每个事件（after_tool_call、on_session_end）都是反馈捕获点 → 写入工作区文件（USER.md/SOUL.md/AGENTS.md）→ 下次上下文组装时预加载 → 强制召回步骤确保不遗忘。但 agent 是被钩子推动的，不是主动的。

- **hermes 有进化**——而且 agent 是**主动**的：自己决定学什么、自己创建 Skill、自己改进 Skill、被 Periodic Nudges 推动保持学习节奏。

**区别不在"有没有进化"，在"谁在驱动进化"：**
- CC：系统驱动（后台流程）
- openclaw：事件驱动（钩子系统）
- hermes：Agent 驱动（自主学习）
