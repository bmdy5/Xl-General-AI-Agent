# 阶段 4：自动记忆 — 跨会话记住偏好

> 老肖 | 2026-05-09

目标：agent 能自动识别并保存重要信息，下次对话自动加载。

验收标准：告诉 agent 一条偏好 → 退出重启 → 问它"我的偏好是什么？" → 正确回答。

---

## 1. 为什么阶段 4 而不是更早

阶段 1-3 是刚需，阶段 4 是体验优化：

- 没有核心循环 → 根本用不了
- 没有搜索 → 不是"通用"agent
- 没有压缩 → 用不久就崩溃
- 没有自动记忆 → 能用，但每次都是"新来的"

**先能用 → 再稳定 → 再聪明**。

## 2. 选型：CC 的模式 + hermes 的接口

### 四个框架怎么记东西

| 框架           | 怎么写入                                   | 怎么检索              | 复杂度 |
| ------------ | -------------------------------------- | ----------------- | --- |
| **CC**       | 模型自己决定什么值得记，调 Auto Memory 写入           | 轻量模型从文件清单中选最多 5 个 | 中   |
| **hermes**   | memory_tool 提供 add/replace/remove/read | 每轮 prefetch 全文注入  | 低   |
| **tinypace** | 后台自动，压缩时存摘要                            | 向量语义检索 + HyDE     | 高   |
| **OpenCLAW** | 后台自动 + 强制召回                            | BM25 + 向量混合       | 最高  |
|              |                                        |                   |     |

### 我选 CC + hermes 混合

**写：CC 模式——模型驱动**

不改系统逻辑，加一个 `save_memory` 工具。agent 在对话中觉得"这条信息以后有用"，就自己调用这个工具存下来。

这和 Anthropic 的设计哲学一致："模型自己决定流程"。不需要后台进程，不需要定时触发。

**接口：借鉴 hermes——action 参数模式**

hermes 的 `memory_tool.py` 用 action 参数区分操作：

```python
save_memory(action="add", filename="user_prefs", description="用户的测试偏好",
            content="用户不喜欢在测试中使用 mock 数据库")
save_memory(action="read")  # 读所有记忆
save_memory(action="replace", old_text="不喜欢 mock", content="必须用真实数据库")
save_memory(action="remove", old_text="过时的信息")
```

这个设计很干净——一个工具覆盖所有记忆操作。

**为什么不用向量检索？**

向量检索需要 embedding 模型 + 向量存储。
目前几十条记忆的规模，全文注入 system prompt 完全够用。
向量检索的价值在记忆上千条后才体现。

## 3. 和已有代码的关系

阶段 1 已经实现了 `MemoryManager`：
- `memory/` 目录存 Markdown 文件
- `MEMORY.md` 做索引
- 启动时 `load_context()` 注入 system prompt

阶段 4 只需要加一个层——**谁来写**。之前是手动写 .md 文件，现在让 agent 通过工具自己写。

```
阶段1:  启动 → MemoryManager.load_context() → 注入 system prompt
         写入：手动编辑 .md 文件 ❌

阶段4:  启动 → MemoryManager.load_context() → 注入 system prompt（不变）
         写入：agent 调 save_memory 工具 → MemoryManager.save() ✅
```

## 4. 与上下文压缩的配合

对比文档里 OpenCLAW 的一个设计值得借鉴：

> 压缩前先写 MEMORY.md——把当前关键信息持久化，压缩才不会丢失

阶段 3 的压缩机在压缩前，自动调一次 `save_memory` 把当前关键上下文写盘。这样即使压缩丢了细节，关键信息还在。

## 5. 验证方式

```bash
./run.sh
> 记住：我在做测试的时候不喜欢用 mock 数据库，必须连真实数据库
# agent 应该调 save_memory 工具

> /exit

./run.sh
> 我之前跟你说的测试策略是什么？
# 期望：agent 回答"你不喜欢用 mock 数据库，必须连真实数据库"
```
