# 阶段 3：上下文压缩 — 长对话不崩溃

> 老肖 | 2026-05-09

目标：agent 聊久了自动压缩旧对话，不爆上下文窗口。

验收标准：连续聊 40 轮不报错，早期对话被自动压缩为摘要。

---

## 1. 为什么需要这个

DeepSeek 上下文 128K tokens。看起来很大，但实际跑起来：

- 每轮对话的 system prompt + 工具定义约 1K tokens
- 用户消息平均 200 tokens
- AI 回复 + 工具结果平均 1K tokens
- **每轮消耗约 2K tokens**
- 30 轮 ≈ 60K tokens，已经接近临界

没有压缩的话只能靠重启。而且越往后模型对早期指令的注意力越低。

四个框架对比文档里对压缩的评价：

| 框架 | 复杂度 | 核心思路 |
|------|--------|---------|
| CC | 高 | "PTL 剥洋葱"——从最早消息逐层剥离，SM 直挂免重摘要 |
| tinypace | 高 | 两阶段：Phase 1 压历史 + Phase 2 压当前轮，92% 触发 |
| OpenCLAW | 最高 | 三级恢复：压缩→截断→报错，最稳健但最复杂 |

## 2. 选型：提取 tinypace 核心，丢掉耦合

tinypace 的 `auto_compact.py` 有 728 行，但它是一个"完整的集成系统"：

```
auto_compact.py 依赖树：
├── SessionState（长期记忆存储）
├── FileRecoveryManager（压缩后恢复文件）
├── MessageNormalizer（消息预处理）
├── tiktoken（精确 token 计数）
├── context_retrieval_service（记忆索引）
└── file_operations（文件行号添加）
```

如果直接抄，等于把整个 tinypace 的 session/state/memory 体系都搬过来。

### 保留什么（tinypace 的精髓）

```
1. 阈值触发：token 超过窗口的 N% 时触发
2. Head/Tail 分割：最后一条用户消息是分界线
   - Head = 之前的旧对话（压缩）
   - Tail = 之后的新对话（保留）
3. LLM 摘要：调模型把旧对话压成一段摘要
4. 摘要替换：用摘要消息替换原始旧消息
```

### 去掉什么

| 去掉 | 为什么 |
|------|--------|
| tiktoken | 用 `len(str)/4 ≈ tokens` 估算，误差 20% 但够用 |
| FileRecoveryManager | 暂时没有"压缩后恢复最近打开文件"的需求 |
| Phase 2 Tail 压缩 | 先只压历史，当前轮不动 |
| Memory 索引 | 阶段 4 的事 |
| 两场景 fallback | 压完还太大？直接截断最早消息 |

### 借鉴 OpenCLAW 的一个设计

对比文档提到 OpenCLAW 的亮点：

> **压缩前记忆刷新**：压缩前先把当前关键信息写入 MEMORY.md

这样即使压缩丢了细节，关键信息已经持久化了。我们的压缩机在压缩前调一次 memory 写入。

### 借鉴 CC 的一个设计

> **熔断器**：连续压缩失败 3 次 → 停止尝试，避免死循环

简单但有效。

## 3. 最终设计

```python
# 触发条件
estimated_tokens = sum(len(str(m)) // 4 for m in messages)
should_compress = estimated_tokens > max_tokens * 0.75

# 压缩流程
def compress(messages):
    1. 找到最后一条 user 消息的位置 → split_index
    2. Head = messages[:split_index]  # 旧对话
    3. Tail = messages[split_index:]  # 当前轮，保留
    4. 调 LLM 把 Head 总结成一段摘要（max 1000 tokens）
    5. 把摘要写入 MEMORY.md（借鉴 OpenCLAW）
    6. 返回 [摘要消息] + Tail

# agent loop 中的位置
async def run(self, user_input):
    if self.compressor.should_compress(self.messages):
        self.messages = await self.compressor.compress(self.messages)
        yield {"type": "compacted"}
    # 继续正常循环...
```

### 关键参数

| 参数 | 值 | 为什么 |
|------|-----|--------|
| 触发阈值 | 75% | 比 tinypace 的 92% 保守——给当前轮留更多空间 |
| 摘要模型 | 主模型（DeepSeek） | 不引入额外模型 |
| 摘要 max tokens | 1000 | 压缩后不应太长 |
| 熔断 | 连续 3 次失败 | CC 的做法 |
| Token 估算 | `len(str) / 4` | 中文≈1.5 字/token，英文≈4 字/token，取 4 偏保守 |

## 4. 验证方式

```bash
./run.sh
# 连续聊 40 轮，每轮说"继续"或问一个新问题
# 观察中间是否出现 "[compacted]" 事件
# 问 agent "我们最早聊的是什么？" → 它能从摘要里回答
```
