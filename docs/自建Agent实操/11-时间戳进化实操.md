# 阶段 6：时间戳进化 — 记忆自动迭代

> 老肖 | 2026-05-09

目标：同主题记忆自动以最新为准，旧知识不会覆盖新知识。

验收标准：存一条偏好 → 改主意了 → agent 自动用最新版本。

---

## 1. 为什么需要这个

没有时间戳的话：

```
第1次对话：用户说"我喜欢简洁回复"
  → agent 存入 "回复风格: 简洁"

第2次对话：用户说"以后详细点解释，多给例子"
  → agent 存入 "回复风格: 详细"
  
第3次对话：两条记忆都在，agent 不知道哪个对
```

有时间戳后：

```
第1次对话：存 "回复风格: 简洁"  (2026-05-09T10:00)
第2次对话：存 "回复风格: 详细"  (2026-05-09T14:00)
第3次对话：启动时排序 → 14:00 > 10:00 → 注入 "详细" ✅
```

## 2. 怎么做的

### 2.1 MemoryManager 改动

| 改动 | 说明 |
|------|------|
| `save()` 返回时间戳 | `2026-05-09T14:30:00Z` 格式 |
| 同文件更新 → 保留旧版 | 新内容顶部 + `<!-- previous version -->` 底部 |
| `_upsert_index()` | 索引中同名条目自动替换为新时间戳 |
| `load_context()` | 按时间戳降序排序，最新优先 |
| 去重 | 同文件名只保留最新条目 |

### 2.2 save_memory 工具改动

| action | 之前 | 现在 |
|--------|------|------|
| `add` | 存了就完 | 返回时间戳，标注"新增"还是"更新" |
| `replace` | 简单覆盖 | 调用 save() 自动进化：新时间戳 + 旧版保留 |
| `remove` | 只能文本匹配 | 新增 `filename` 参数直接指定 |
| `read` | 随便列出 | 按时间戳排序，最新在前 |

### 2.3 system prompt 新增

```
### Evolution Rules (时间戳进化)
- Every memory has a timestamp. Newer timestamps override older ones.
- If I change my mind, use 'replace' to evolve the memory.
- Old version preserved at file bottom, only latest injected.
```

## 3. 代码来源

| 设计 | 来源 |
|------|------|
| 时间戳格式 | ISO 8601（openclaw 的日期文件思路） |
| 最新优先排序 | tinypace Strategy B（只保留最新摘要） |
| 旧版保留 | hermes 迭代合并（merge not stack） |
| 索引更新 | CC 的 MEMORY.md 增量更新 |
| `_upsert_index` | 自创——简单正则替换 |

## 4. 验证方式

```bash
./run.sh

# 第1轮：存偏好
> 以后回复都用中文

# 第2轮：改偏好
> 以后回复用英文

# 退出重启
> /exit
./run.sh

# 检查记忆：应该显示两条，但最新的优先
> /memory

# 问 agent：应该用英文回复
> 你好
# 期望：英文回复（因为最新的记忆是"用英文"）
```
