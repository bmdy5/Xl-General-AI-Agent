# 📡 QQ Agent 消息网关控制与防死锁（CSMA/CD）及疲劳打盹机制维护手册

本手册旨在详细阐述肖亮个人 AI 代理（XL Agent）中高级消息路由网关（`QQGateway`）的载波监听冲突检测（CSMA/CD）协议、疲劳打盹状态机以及亮哥主控特权等核心机制。通过本手册，后续维护人员可轻松理解底层逻辑、进行参数调优并执行自动化测试。

---

## 🛠️ 1. 核心机制设计

网关消息路由控制的引入，是为了在多 Bot 或高频私聊互动中实现**抗高并发死锁**、**合理配额 Token 计费**和**防大模型 CPU/Token 资源恶意过载（物理降温）**。

### 📡 A. CSMA 载波监听与退避 2.0
* **载波监听（Carrier Sense）**：
  * 当网关监听到用户消息时，并不立刻向 Agent/LLM 发起提问，而是记录 `self._last_receive_time[session_key] = time.time()`。
  * 紧接着执行非阻塞的 `await asyncio.sleep(csma_backoff_seconds)` 载波监听顺延。
* **退避顺延（Backoff）**：
  * 如果在等待期内用户（或另一个 Bot 快速跟发）发送了新消息，`self._last_receive_time` 会被覆写为最新的时间戳。
  * 等待结束后，若检测到 `_last_receive_time > 本次消息的进入时间`，当前协程将立刻静默废弃返回。这保证了高频发帖时的消息合并与总线避让。

### 🚫 B. CSMA/CD 两阶段冲突检测与暂存避让
* **冲突检测（Collision Detection）**：
  * **第一阶段（推理中途拦截）**：在大模型流式逐字输出循环的首行进行强判定，一旦检测到推理期间用户又发送了新消息（即 `_last_receive_time > task_start_time`），大模型流式生成将立刻触发 `break/return`，中断运行。
  * **第二阶段（最终发送前拦截）**：在 `finally` 发送缓冲块中再次进行冲突时序判定，若检测到冲突，立刻强行将输出缓冲区 `buf` 置空，决不发送任何半成品碎屑，绝不污染聊天视窗。
* **暂存队列避让**：
  * 当大模型正在执行某些高延迟工具（例如爬虫、生图、代码运行等）时，新灌入的消息会先进入暂存队列 `self._message_queues`。
  * 一旦在 `finally` 块中检测到冲突时序，网关将**跳过暂存队列的 pop 机制**，把控制权交还给导致冲突的最新发言者，避免出现消息顺序错乱。

### 💤 C. Token 物理计费与打盹梦境净化状态机
* **流式 Token 汇总**：
  * 引入了 `total_sent_tokens` 累加器。在所有发送出口（包括中间流式分句、工具调用前发送以及最终 `finally` 缓冲发送点）进行 Token 长度的物理累加，精准解决流式分段发送导致的计费遗漏。
* **物理打盹（Nap Mode）**：
  * 非管理员（亮哥以外的同事或第三方用户）在私聊或群聊中与小萤对话，其产生的 Token 会乘以疲劳系数累加进 `_fatigue_levels[session_key]`。同时大脑由于时间推移会以每分钟 `2.0%` 的速度自然消退疲劳。
  * 当疲劳度达到 `100.0%` 时，触发物理打盹。打盹启动时，大模型会高情商、可爱地发表一句用脑过度吐槽宣告（支持**单气泡三段呼吸律**与动作描写，如“脑细胞烧光了”），然后进入 **深度冷却梦境**。
* **梦境进化（Evolution）**：
  * 在打盹期间，网关将物理屏蔽该用户的所有新消息（静默拦截，直接 return）。
  * 协程会备份并清空 Agent 会话内存（Token 降为零），异步拉起深度做梦与技能进化任务 `trigger_deep_dream_evolution`。
  * 冷却期结束后，疲劳度重置为 `0.0%`，大模型会动态生成醒来宣告（“充满电上线啦”），重新恢复会话交互。

### 👑 D. 亮哥主控特权与唤醒穿透
* **一键暂停/恢复**：亮哥（管理员）在私聊中发送 `"暂停私聊"`/`"恢复私聊"`，可一键控制全局非主人私聊服务的启停。
* **特权强行穿透**：即使在非主人因高疲劳处于“打盹冷冻梦境”或“暂停”期间，亮哥的指令也具有最高优先级，能够强行穿透拦截、唤醒大脑并直接响应。

## 📊 2. 系统时序图

以下是 CSMA/CD 与暂存队列避让的时序流：

```
 用户 (User)                QQGateway                Agent/大模型
     │                          │                          │
     │── 1. 发送消息 "Hello" ──>│                          │
     │                          │── 2. 启动载波监听 2s ───>│
     │                          │   (CS 延迟顺延等待...)   │
     │                          │                          │
     │── 3. 插嘴 "Wait!" ──────>│                          │
     │   (触发 Collision!)      │                          │
     │                          │── 4. 冲突判定 (CD 触发)  │
     │                          │    废弃前序 "Hello" 协程 │
     │                          │    退避并响应 "Wait!" ──>│
     │                          │                          │
     │                          │                          │── 5. 流式输出 ──>
     │<── 6. 接收完整流畅消息 ──│<─── [SPLIT]/Buffer ──────│
     │                          │                          │
```

## ⚙️ 3. 环境变量与核心参数调优指南

我们已经将所有核心控制参数与底层逻辑进行了解耦，支持通过项目根目录下的 `.env` 文件进行热配置，无需改动任何 Python 代码：

| 环境变量键名 | 默认值 | 作用与调优建议 |
| :--- | :--- | :--- |
| `QQ_ADMIN_ID` | `1705919142` | **管理员（主人亮哥）的 QQ 号**。用于识别特权开关指令、穿透打盹拦截。 |
| `QQ_CSMA_BACKOFF_SECONDS` | `2.0` | **载波监听退避等待秒数**。高并发聊天群可调大至 `3.0`s 以增强消息合并，私聊或追求极速响应可调小至 `1.0`s。 |
| `QQ_FATIGUE_SLEEP_MINUTES` | `15.0` | **脑力过载打盹深度梦境休眠分钟数**。在此期间非主人消息会被网关直接丢弃。测试时可设为 `0.1` 快速验证复苏。 |
| `QQ_FATIGUE_RATE` | `0.4` | **疲劳计费扣分系数**。值越大扣分越敏感。每个生成的 Token 乘以该系数即为扣除的疲劳值。设为 `0.1` 可允许更长对话，设为 `0` 则完全关闭疲劳打盹。 |

> [!TIP]
> 修改 `.env` 后，只需重启 `python main.py --gateway` 即可无感应用，极其方便。

## 🧪 4. 维护与自动化验证

为了保证每次代码重构或新增技能后，网关的核心路由不发生任何逻辑回归，请务必在提交前运行以下命令：

### 🏃 运行集成测试
```bash
./venv/bin/python3 scratch/test_csma_cd_fatigue.py
```

### 📋 4 大测试用例覆盖
1. `test_private_chat_paused_commands`：验证管理员一键“暂停/恢复”非主人私聊的指令响应与拦截态切换。
2. `test_carrier_sense_backoff`：模拟 0.5s 连续跟发，验证第一条消息自动被 Carrier Sense 退避废弃，只响应最后一条。
3. `test_collision_detection`：在大模型流式推理中途强行注入新消息，验证大模型强行 break 退出、buf 置空并不产生碎屑发送。
4. `test_private_fatigue_and_sleep`：模拟非管理员会话 Token 累加，达到 100% 后触发高情商吐槽宣告、打盹冷冻期消息屏蔽，以及醒来后的苏醒复苏机制。
