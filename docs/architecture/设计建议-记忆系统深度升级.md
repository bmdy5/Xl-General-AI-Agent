# 设计建议：记忆系统深度升级 (XL Agent 专属版)

> 本文档基于对 XL Agent 现有架构（L1-L6 分层、自进化系统）的深度分析，结合 Hermes、Claude Code 及 MemOS 的核心设计哲学，提出的针对性升级方案。
> 核心原则：**保留 XL Agent 自进化基因，拒绝盲目生搬硬套，追求 prompt 稳定性与缓存友好。**

---

## 1. 现状透视：XL Agent 的记忆基因

目前 XL Agent 的记忆架构已经非常扎实，具备了以下优势：
- **分层清晰**：L1-L6 的分层逻辑（从会话持久化到自进化规则）比大多数开源项目更具工程性。
- **崩溃安全**：JSONL append-only 保证了数据的极端可靠性。
- **自进化驱动**：具备“自主学习”和“反馈驱动规则”的闭环能力。

**待突破的瓶颈：**
- **细节检索盲区**：JSONL 难以进行高效的全文检索，Agent 容易“记住大意（MEMORY.md），遗忘细节（Session 历史）”。
- **知识物化不足**：记忆大多停留在文本层面，尚未完全转化为可复用的“程序性技能（Skills）”。
- **记忆冲突隐患**：缺乏对过期或自相矛盾记忆的自动清理与合并机制。

---

## 2. 竞品启示：取其精华，去其糟粕

| 借鉴点 | 来源 | 在 XL Agent 中的落地思路 |
| :--- | :--- | :--- |
| **Prompt 稳定性** | Hermes | 确保 L5/L6 注入的记忆块（MEMORY BLOCK）位于 Prompt 的固定位置，优化 Prefix Caching，降低延迟和成本。 |
| **情景回忆 (Episodic)** | Hermes/SQLite | 不改变 JSONL 主存地位，引入 SQLite FTS5 作为“影子索引”，提供 `search_history` 工具。 |
| **记忆冲洗 (Flush)** | OpenClaw | 在 L2 上下文压缩触发前，强制执行一次 L3/L4 写入，确保压缩不丢失当前关键信息。 |
| **智能合并 (Merge)** | MemOS | 在 `save_memory` 时加入 LLM 审计，识别冲突记忆并执行合并，而非简单的文本追加。 |

---

## 3. 三大核心升级方案

### 方案 A：情景回忆层 —— SQLite FTS5 影子索引
**目标**：赋予 Agent “回忆过去任何对话细节”的能力。

*   **实现逻辑**：
    1.  修改 `agent/session/handler.py`，在每条消息写入 JSONL 后，同步打入一个本地 SQLite 数据库。
    2.  利用 SQLite 的 `FTS5` 虚拟表实现极速全文检索。
    3.  **工具化**：新增 `search_sessions` 工具。当用户问及“我之前说过什么”或“某项任务的历史细节”时，Agent 自主调用。
*   **优点**：不增加每轮对话的 Token 负担，只有在需要时才按需加载。

### 方案 B：程序性技能层 —— 技能作为子代理配置
**目标**：将“知道怎么做”转化为“自动派人去做”。

*   **实现逻辑**：
    1.  将 `README` 中提到的“任务→技能转化”物化。
    2.  **Skill 定义**：一个 Skill = 一个包含特定 System Prompt + 专用工具集的 Markdown 配置文件（存放在 `agent/skills/`）。
    3.  **调用逻辑**：修改 `spawn_agent` 工具。支持加载 `.skill` 文件。
    4.  **进化闭环**：在 `on_session_end` 时，由 Pro 模型判断本次任务是否具备“高复用价值”，若是则自动生成并持久化该 Skill。

### 方案 C：语义冲突处理 —— “先审计，再存储”
**目标**：解决“减肥案例”中的新旧记忆冲突。

*   **实现逻辑**：
    1.  升级 `MemoryManager.save()` 方法。
    2.  **冲突检测**：在写入文件前，读取同类记忆（通过描述匹配），由 Flash 模型判断新旧信息是否矛盾。
    3.  **智能合并**：若矛盾，调用模型执行 `merge_memories(old, new)`，用最新的事实更新记忆，保持记忆库的“干净”。

---

## 4. 实施路线图

1.  **第一阶段 (Index & Search)**：实装 SQLite FTS5 影子索引，上线 `search_sessions` 工具。
2.  **第二阶段 (Proceduralization)**：规范化 `.skill` 文件格式，升级 `spawn_agent`，实现初级技能自动提炼。
3.  **第三阶段 (Semantic Audit)**：集成记忆合并逻辑，优化 `save_memory` 工具的幂等性与冲突检测。

---

## 5. 结论

XL Agent 不需要变成另一个 Hermes。通过引入**按需检索（SQLite）**和**技能物化（Skills as Configs）**，我们可以让它在保持“极简、稳健”的同时，真正具备跨会话、跨时间的深度工程能力。
