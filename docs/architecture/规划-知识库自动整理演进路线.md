# 个人知识库全天候自动整理演进路线

基于对当前知识库状态与自动化容忍度的综合评估，自动化笔记整理功能将按以下三个模式逐步演进：

## 模式一：被动触发（类似 Code Formatter） [✅ 已完成]
**当前状态：** **已落地实装**。成功封装为 `organize_notes` 工具，具备了超长 Token 过滤阻断、物理备份原稿（.bak）防灾、正则剥离 LLM 冗余外壳以及强制二次权限确认拦截等完备安全机制。

* **怎么做**：在 Agent 体系内增加专门的“整理命令”（例如通过新增的 `organize_notes_tool`），在聊天框输入“帮我格式化一下最近的笔记”即可触发。
* **执行逻辑**：
  1. Agent 调用 `read_file` 扫描指定文件夹（如 Inbox）下近期修改的 Markdown 文件。
  2. 调用 LLM（例如 Gemini 2.5 Flash/Pro）按预设排版规范（加黑关键术语、统一层级标题、自动补充 YAML Frontmatter 标签）对文本进行重写。
  3. 调用 `edit_file` 将格式化后的内容覆盖原文件。
* **优点**：可控性极高，完全避免 Agent 出现“暴走”乱改核心笔记的情况。在建立足够信任前，这是最安全的做法。

## 模式二：定时巡检（类似垃圾回收器） [✅ 已完成]
**当前状态：** **已落地实装**。修复了 `task_queue.py` 定时任务无法重复执行的 bug。在 `gateway.py` 成功开启了后台 `_daemon_loop`，并全局升级为携带 `result` 属性的 `_PermEvent` 状态对象，彻底根治了多任务异步串行时的“并发竞态脏读”隐患。如今，后台定时扫描任务触发时，主人可以直接在手机 QQ 私聊中一键“y/允许”后台静默安全越权修改，交互逼格拉满。

* **怎么做**：基于现有的 `task_queue.py` 定时任务队列，写入一个每周或每晚自动运行的后台常驻任务。
* **执行逻辑**：
  1. Agent 后台巡检“收件箱（Inbox）”或“未分类”文件夹。
  2. 读取其中杂乱的草稿、截图 OCR 文本或零散链接内容。
  3. LLM 自动理解上下文，进行高精度分类并打标签。
  4. 利用内置 Bash 工具或 File 工具，将文件自动 `mv` 到 Obsidian 里对应的专业知识归档目录（如 `/计算机科学/AI/` 或 `/生活/投资/`）。
* **优点**：真正实现“把知识放进去就不用管了”的懒人体验，打造自动运转的数字大脑。

## 模式三：深度知识图谱重构（终极形态）
**当前状态：** 终极目标（基于 `notes_fts` 与 BGE-m3 向量化的混合检索）

* **怎么做**：利用已有的多层记忆架构、SQLite 全文检索及未来将引入的本地 Embedding 库，实现知识点的自动串联。
* **执行逻辑**：
  1. 笔记流转与格式化后，Agent 将自动提取核心实体。
  2. 自动在全库回溯检索。例如扫描到今日新建的“DeepSeek V4 Pro”笔记，会自动回溯半年前的“大模型推理成本”相关笔记。
  3. 在两篇或多篇关联笔记中，自动插入 Obsidian 规范的双向链接（`[[ ]]`），构建知识图谱。
* **优点**：从单纯的文件收纳升级为立体的知识网络，彻底解决长尾知识遗忘问题，属于知识管理的终极利器。
