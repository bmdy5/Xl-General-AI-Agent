## 一、XL 是什么

XL 是肖亮的个人 AI 代理。基于 ReAct 循环 + 工具调用 + FTS5 记忆检索。核心设计原则：**XL 不擅长写代码，擅长分析/设计/研究**。代码由教练（Reasonix）实现。

## 三、记忆系统

### 3.1 架构

```
情景记忆（FTS5 全文搜索）
├── 来源：工具调用上下文自动存入 JSONL
├── 索引：SQLite FTS5 虚拟表，BM25 排序
├── 中文：CJK 字符自动分字
├── 降级：FTS5 → LIKE → JSONL grep 三层保护
└── 注入：关键词匹配度排序，Top-5 条

知识库（学习笔记索引）
├── 来源：扫描 /Desktop/学习笔记/ 目录
├── 处理：长文本分块（max_chars=500）后索引
└── 展示：memory_block 中"相关知识"区域
```

### 3.2 记忆类型

| 类型 | 用途 | 来源 |
|------|------|------|
| `[user]` | 用户偏好、个人信息 | 主动保存 |
| `[learn]` | 学习笔记、知识文档 | 自动索引 |
| `[feedback]` | 用户纠正、经验教训 | on_session_end 分析 |
| `[project]` | 项目决策、架构记录 | 主动保存 |

### 3.3 API

```python
await mm.save("filename", "[user] 描述", "内容")
results = mm.search_memories("关键词")    # FTS5 搜索
mm.list_memories()                          # 列出所有
mm.remove("filename")                       # 删除
```

## 五、Stitch 集成（已修复）

### 5.1 问题与修复

Stitch MCP 调用经历了多次修复：

| 问题 | 根因 | 修复方式 |
|------|------|----------|
| MCP 子进程无输出 | `npx` 包裹层阻断 stdin/stdout 管道 | 改用直接二进制路径 `/Users/xiaofeng/.npm/_npx/d7bcf1e9427e7044/node_modules/.bin/stitch-mcp` |
| gcloud 认证失败 | PATH 中没有 gcloud SDK | 在 env 中设置 PATH，包含 gcloud bin |
| Python 版本冲突 | gcloud 检测到不兼容的 Python | 设置 `CLOUDSDK_PYTHON` 环境变量 |
| 读取响应超时 | MCP 输出 JSON 不带换行符 | 改用 `stdout.read()` 替代 `readline()` |
| HTML 代码未下载 | 工具只返回了预览链接 | 解析 JSON 响应，从 `htmlCode.downloadUrl` 下载 HTML |

### 5.2 当前稳定调用方式

```python
# 通过 bash shell 调用（已验证最稳定）
script = f"""export GOOGLE_CLOUD_PROJECT=stitch-496215
export PATH="/path/to/gcloud:/path/to/node:$PATH"
export CLOUDSDK_PYTHON=/path/to/python3
cat <<'MCP_INPUT' | /path/to/stitch-mcp 2>/dev/null
{init_json}
{notif_json}
{tools_call_json}
MCP_INPUT"""

result = subprocess.run(["bash", "-c", script], timeout=200)
# 解析 result.stdout → 提取 htmlCode.downloadUrl → 下载 HTML
```

### 5.3 环境要求

- Google Cloud Project: `stitch-496215`
- gcloud SDK: `/Users/xiaofeng/.stitch-mcp/google-cloud-sdk/bin/`
- Node.js: `/Users/xiaofeng/.nvm/versions/node/v25.8.0/bin/`
- 认证: `gcloud auth application-default login`

## 六、DuoAgent 圆桌讨论

### 6.1 架构

```
用户浏览器 → FastAPI :8899 → XL LLM
     ↑            ↑
     └── SSE 流 ──┘

每个 Agent 角色 = 一次 LLM 调用，带不同 persona
```

### 6.2 启动

```bash
xl --duoagent              # 启动服务器
# 浏览器打开 http://localhost:8899
```

### 6.3 角色模板

| 角色 | 风格 |
|------|------|
| 主持人 🎙️ | 中立、归纳 |
| 正方 💡 | 积极、论证 |
| 反方 ⚡ | 理性、质疑 |
| 专家 📊 | 严谨、数据 |
| 自由人 🌈 | 创意、发散 |
| 现实派 🏔️ | 务实、落地 |

### 6.4 讨论流程

```
用户给话题 → 主持人开场 → 各角色按轮次发言 → 主持人总结
```

后端每轮依次调 LLM（带 persona + 已有讨论上下文），结果通过 SSE 推送到前端。

## 七、进化系统

### 7.1 流程

```
工具审计 → 模式检测 → 规则生成 → 规则注入 → 效果验证
```

### 7.2 模块

| 模块 | 功能 | 文件 |
|------|------|------|
| `audit_tool_call` | 每次工具调用记录耗时、成功/失败 | evolution.py |
| `detect_task_pattern` | 发现重复操作模式 | evolution.py |
| `on_session_end` | 会话结束后提取 learnings | evolution.py |
| `evolve_rules` | 从 feedback 记忆中生成规则 | evolution.py |
| `EvolutionEngine` | 规则存储 + 置信度追踪 + 自动注入 system_prompt | evolution_apply.py |

### 7.3 自动记忆纠正

XL 在交互模式中，用户输入包含纠正信号（"不对"、"错了"、"应该"）时，会自动保存为 `[auto]` 记忆。由 `evolution.py` 的 `on_session_end` 在会话结束时分析。

## 九、XL 训练方法

### 9.1 训练原则

1. **代码归教练，分析归 XL** — 教练（Reasonix）写代码，XL 做分析/设计/研究
2. **每次只加一点，测试后提交** — 新功能开分支，测完合 dev
3. **不引入冗余** — 已有功能不再重复实现
4. **行为教训自动记忆** — XL 被纠正时自动存 `[feedback]` 记忆

### 9.2 训练流程

```
① 教练分析需求 → 设计方案
② 开新分支（feat/xxx）
③ 教练实现代码
④ 测试（功能测试 + 集成测试）
⑤ 提交到分支 → 合并到 dev
⑥ XL 记忆教训
```

### 9.3 已有训练记录

见 `agent培养/训练日志/` 目录，包含 14 篇训练日志和验证报告。
